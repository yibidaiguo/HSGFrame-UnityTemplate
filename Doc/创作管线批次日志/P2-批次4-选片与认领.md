## 选片为什么不并进 `PoolPushPlanner`

`PoolPushPlanner` 的单位是**需求**（`pool.push REQ-0042 --事件 待验收`），出站要回写需求的下游字段。
选片的单位是**资产**——一个需求下可能有十个资产各自选片——而且选片**不回写任何下游字段**，
只发卡片。硬塞进需求级的事件表，会逼着事件表多带一个「资产 id」参数，
而其余五个事件全都用不上它。所以选片走独立的 `SelectionOutboundPlanner`，
`PoolPushPlanner.cs` 这一批**一个字没改**（已用 `git diff --stat` 验过是零输出）。

## 落地

**选片出站**：`SelectionCard`（卡片模型，按钮 = 序号 → `换一批` → `我自己来`，
第 3 轮起挂提示语）、`SelectionCardBuilder`（扫变体目录装配）、
`SelectionOutboundPlanner`（包成出站意图信封）、命令 `art.select`。

**合格变体的判定**：顶层图片文件（`.png` `.jpg` `.jpeg` `.webp`）**且有同名 `.溯源.json` 边车**。
没边车的不算合格变体并出一条 finding——这是子文档 06 §二 第 3 步「机检预筛」的最低一档：
**边车缺失说明这张图来路不明**。尺寸 / 格式 / 命名的机检不在这一批，那是
`AssetSpecInspector` 的活，等真资产文件落地再接。

**专项认领入站**：`EpicClaimEnvelope`（独立信封）、`EpicClaimIntake`（幂等 + 只写认领字段）、
`EpicClaimWriter`（显式 / 隐式两条路）、命令 `pool.claimpull` / `pool.claim`。

## 本批新增的锁定决策

32. **专项认领入站走独立信封与独立收件箱子目录（`Pools/Inbox/专项/`），不复用需求信封。**
    认领字段是「**下游成员编辑所有、工程只读同步进来**」（子文档 02 §一），
    而需求信封的字段所有权正相反。混进同一个信封，幂等键与字段所有权两套语义会打架。
33. **入站只许改专项文件的 `认领` 与 `来源` 两个键**，其余字段一字不动；
    信封里多带的键**忽略并报一条 finding**（不是静默吞掉，也不是拒收整封）。
34. **显式认领可跨默认职责，隐式认领不许。** 隐式认领两条硬前提缺一不写：
    该职责当前无人认领 + 该 open_id 的默认职责包含这个职责。
35. **认领没写成功不算失败。**「已认领过」「该职责已有人」都是正常结果，
    `pool.claim` 照样返回 Success 并说清没写的原因——让门禁为这个红没有道理。

## 执行后端这一轮报上来的三件事

1. **`EpicClaimIntakeReport.Rejections` 的元素类型改了——这是我任务书的错。**
   任务书写的是 `IReadOnlyList<RejectionNotice>`，但仓库里 `RejectionNotice` 是个
   **静态写盘类**（只有 `RejectionNotice.Write(...)`），根本不能当列表元素类型。
   它改成 `IReadOnlyList<PoolFinding>` 并说明了理由。**这个改动是对的**，
   语义也对得上——命令层「逐条列出」正好用 `PoolFinding.ToDisplayText()`。
2. **红灯证据是「实现完成后临时改坏 → 确认红 → 恢复」，不是严格的先写测试后写实现。**
   它主动标了出来，没伪装成 TDD。三处改坏点（边车判断反转 / 认领写入置空 /
   默认职责判断反转）各自打红了对应用例。
3. **它往 `/tmp` 写过一次门禁参数文件**（沙箱把 `/tmp` 映射进仓库内的 `tmp/`），
   当场发现并删干净了。Claude 验收时复查过：`tmp/` 不存在，`git status` 干净。

## 已知缺口（不阻塞，记着）

- **`art.select` 只产出站意图信封，不真发卡片。** 真发卡片要消息卡片 port 的 driver，
  而飞书 API 不在可验范围（锁定决策 6）。
- **`换一批` 与 `我自己来` 只是按钮文本，没有对应的回调命令。**
  「反馈词追加进 prompt、预算计数」（子文档 06 §二 第 5 步）要等 `art.generate`。
- **隐式认领没有被任何调用方自动触发。** `EpicClaimWriter.RecordImplicitClaim` 写好了，
  但「首次处理该专项卡片」这个时机点在引擎里，引擎还没接（P4）。
  现在只能由 `pool.claim --IsImplicit` 手动触发。
- **同步水位仍未做**（`Config/创作管线/同步水位.json`）。`pool.claimpull` 和 `pool.pull` 一样，
  只从已经躺在收件箱里的文件读，不负责把文件弄进来。
- **`art.` 命令族不在 `POST /cmd` 白名单里**（白名单是 `task.` / `pool.` / `bridge.` /
  `engine.` / `conflict.` / `spec.` 六族，锁定决策 19），所以面板点不了 `art.select`。
  这是既有约束，不是本批引入的。
