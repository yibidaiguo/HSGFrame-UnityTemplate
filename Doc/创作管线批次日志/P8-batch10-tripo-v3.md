## 三、这一批真正的收获：用错误码给端点画地图

积分是 0，一个任务都跑不成——但**这不妨碍把形状核准**，因为下游把三种拒绝分得很干净：

- `4001 端点不存在` → 这个 URL 根本不在
- `1004 参数非法` → URL 对了，形状不对
- `2010 积分不足` → URL 和形状都对了，只差钱

所以「回 2010」就是形状正确的**证明**。两条提交路径都做到了这一点。
顺带实证出两件文档没说清的事：

1. **v3 没有 `/upload` 也没有 `/upload/sts`**（都回 4001），
   所以本地图片直传这条路**现在走不通**，参考图必须是下游能直接 GET 的地址。
2. **官方快速开始页上的 `tripo-v3.1` 是错的**，服务端自己列出了允许值。
   桥现在本地就拦，省一次注定 1004 的调用。

## 四、顺带修好的一处：错误码判断从 HTTP 状态码换成服务端 code

原来只在 403 里分 2010/1005。现在**服务端 `code` 优先于 HTTP 状态码**——
同一个 404 底下 `2001 任务不存在` 与 `4001 端点不存在` 是完全不同的两件事，
按 HTTP 状态码判会把「base URL 写错了」印成「任务没找到」，
那正是待办 3 这笔债当初能潜伏那么久的原因。

1004 的人话现在明说**「是我们发的请求形状不对，不是账号问题」**——
这句话是给下一个看到报错的人省一天的。
