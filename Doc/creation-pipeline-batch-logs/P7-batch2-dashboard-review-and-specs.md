## 验收时发现：面板从 P4 批次二起就是全白的

**这一批最重要的产出不是四个新页，是发现整个面板根本打不开。**

`CreationPanelPage.cs` 里那段 JS 住在 C# 的 verbatim 字符串里。
verbatim 串里 `""` 是**一个**引号，所以三元的空串分支写成 `: "")`
吐出来的是 `: ")`——**半个字面量**。整份脚本当场 `SyntaxError`，
十五个页签一个都不生成，页面永远停在「加载中…」。

这一行是 `de066d0`（**P4 批次二**）带进来的。也就是说：

- P4 批次二说「面板加了任务图/冲突/晋升三页」——**那三页从来没渲染过**；
- P2 批次六说「面板加了资产/设计池/供给对账三页」——**在 P4 批次二之后也一起白了**；
- 中间每一批的 `dotnet build`、`dotnet test`、全量 `gate.ps1` **全是绿的**。

**为什么全绿**：C# 编译器不解析字符串里的 JS；单元测试只测读取器（C# 侧）；
门禁没有任何一道会去解析那段脚本。**没有人真的打开过面板。**

修法是把空串分支写成 JS 单引号 `''`（verbatim 串里单引号不用转义）。

### 补了两道拦它的测试

`CreationPanelScriptTests`：

1. **`EveryScriptLineHasBalancedQuotes`**——抠出 `<script>` 正文，
   逐行数单双引号是否成对。面板脚本基本一行一句、没有跨行字符串，
   所以落单的引号就等于「吐出了半个字面量」。**粗糙但有效。**
2. **`EveryPageHasItsRenderFunctionDefined`**——页面表点名的 `渲染xxx`
   必须真的定义出来，否则那一页点开是空白。

**真验过能抓**：把老 bug 的形状放回去，第一条当场红并点名三处；恢复即绿。

## 「读不成」不许显示统计数字

放行流水页与提案待批页在 `Loaded` 为 false 时**整页只给原因，一个数字都不给**
（决策 42）。残缺的流水拿来印「问题 0 条」，比不显示糟得多。

**「空流水」与「读不成」是两回事**：文件不存在时 `Loaded` 是 true、总数 0——
空账本是正常状态，不是读失败。真跑验过。

## 等待时长的口径写在页面上

终审队列的「等待时长」是按**状态文件最后修改时间**算的，不是进关卡时间——
`状态.json` 里根本没有进关卡的时间戳。这句话**印在页面上**，不是只写在代码注释里。
把一个没有的东西说成有，是决策 20 的同类。

## 已知缺口（不阻塞，记着）

- **引号成对只是启发式。** 它拦得住「吐出半个字面量」这一类，
  拦不住括号不配对、变量名写错这类语法错。**真正的保险是有人打开面板看一眼**——
  或者哪天给门禁接一个真的 JS 解析器。
- **面板脚本仍然是一整块 verbatim 字符串。** 只要还这么写，
  引号转义就会一直是雷区。要根治得把 JS 挪成独立的 `.js` 资源文件。
- **终审队列的「等待时长」口径是将就的**（状态文件 mtime），
  真要准得在 `状态.json` 里记「进关卡时间」。
- **审查页没有审查包五件套。** 子文档 04 §三·五 要的是变更地图/方案对照/预审报告/
  验收报告/分组 diff——那要先有人组装审查包，而 `ReviewPackageBuilder`
  在生产代码里**至今零调用方**（P6 批次三记的那条）。本批只做了队列。
- **规范页是只读的**，新增规则（人述 → AI 生成）与方向文档管理都没做（子文档 04 §四）。
- **按钮的姓名输入不能含空格**（`/cmd` 按空白分词，P4 批次二就记着）。
