# P8 批次 11 · 面板全面重做：从「十六个一样的按钮」到能用的工作台

> 上游：[创作管线P8计划](../creation-pipeline-p8-plan.md)。
> 起因是用户一句话：**「模块区分不清楚、功能网页不好用、用户体验不好」**，外加一句「要美观、可视化清晰」。
> 批次 8 的已知缺口里写着「面板另外十四页这批没动、也没逐页看过」——这一批把那笔账还了。

## 一、原来的面板差在哪

真开一次，四条问题当场立住：

| 问题 | 原来的长相 |
|---|---|
| **模块区分不清楚** | 十六个页按钮平铺在一行，同样大小、同样颜色、没有分组。「晋升」「提案待批」「供给对账」三个名字，外人看不出哪个管哪块 |
| **不知道自己在看什么** | 每页只有一个表格标题，没有一句话说明这页的职责与数字来源 |
| **切页即失忆** | 地址栏不变，刷新回总览，某一页发不出去也收藏不了 |
| **数据不知多旧** | 没有刷新按钮、没有自动刷新、没有「几秒前读的」 |
| **表格用不动** | 十六页全是裸表格：不能搜、不能排、长文本撑爆列宽 |
| **总览只有六个数** | 看完仍不知道该去哪一页；卡片不可点 |
| **错误文案说谎** | 任何一页取数失败都写「面板未配置仓库根时会是这个结果」——而网络失败、接口 500 时这句话是**假的** |
| **输入随重绘蒸发** | 裁决人填一次，一刷新就没；任务图那页为此专门 hack 了一段保值代码 |

## 二、改法

**信息架构**：十六页按职责分六组进左侧栏——纵览 / 需求与调度 / 资产与设计 / 质量与放行 /
治理与规范 / 下游设施。每页配一句「这一页是干嘛的、数字从哪来」，写在页头，也做导航项的悬停提示。
导航项右侧带徽章（条数 / 红黄绿），**导航本身成为一层信息**，而不是十六个一样的按钮。

**可视化**：总览并发拉七个接口，给出 KPI 卡（可点，点进对应页）、「轮到人动手的」四类事、
需求状态堆叠条、门禁逐道方块阵、下游供给环形进度。任务图从表格换成**真的分层 DAG**：
按依赖深度分列、贝塞尔连线；**成环的工作项不画进层里**——它没有深度，硬塞进第 0 层是编造。
资产页给变体收敛进度条，下游页给装机进度环与字段徽章。

**好用**：hash 路由（`#/gates` 可刷新、可收藏、前进后退）、刷新按钮 + 可选自动刷新、
「几秒前读的」时间戳、每页过滤框（表格与卡片都滤）、点表头排序、亮暗主题、
命令台收进抽屉（默认不占地方，带历史与常用命令）、快捷键（`/` `r` `[` `]` `c` `t` `?`）。
「操作人」提到页头统一一处并存本机，冲突页与提案页共用——那段保值 hack 一并删掉。

**「已供给」的绿加了一句话**：它只说明产物往下游推过一次，不说明下游那边的形状跟上了。
这两件事真的会分家——推过之后 schema 又加了列，供给目录照样在，绿照样绿
（并发跑 P8-10 的那个会话正好撞出这个：`bridge.apply` 原来遇到同名表整张跳过，加的列补不下去）。
形状跟没跟上，看的是供给对账页的**对账**列，不是**供给**列。

**说实话**：取数失败分三类给三种文案（未配仓库根 / 连不上服务 / 接口出错），不再一律甩那句假话。
门禁「未跑」、操作人没填这类**不是错误**的情形改用中性的提示态，红色只留给真错——
拿红色说没出的错，跟把没跑的门禁说成绿是同一种病。

## 三、顺手拆掉的一颗雷

面板的 HTML/CSS/JS 原先拼在 C# 的 verbatim 字符串里，一个写错的引号转义就吐出半个字面量，
整份脚本语法错、十六页一页都不渲染，而**编译、测试、全量门禁全是绿的**（P4 批次二到 P7 批次二，
面板白了三个批次没人发现）。这一批把正文挪进 `Tools/Dashboard/Web/panel.html` 与 `panel.js`
两个真文件，编译时嵌进程序集，`CreationPanelPage` 装配时把脚本填进 HTML 的占位处；
占位记号找不到就当场抛——宁可炸，也不交一份看着正常的死页面。

`CreationPanelScriptTests` 那道「每行引号必须成对」的启发式**一个字没改**，
代码去适配它：12 处跨行字符串拼接改写成先取变量再拼，`转义()` 里的两个裸引号写成
`\u` 转义。这道护栏在真文件里价值变小了，但它现在拦的是别的东西——顺手留着不亏。

## 四、真点了一次「试跑」按钮，点出四个问题

批次 8 的已知缺口里写着「**试跑按钮没真点过**」，还附了一句推断：
「`bridge.*` 在放行族里，理论上通」。这一批真点了。**那句推断是错的，而且底下压着四件事。**

**① 面板一跑起来，它自己的每个命令按钮就都是坏的。**
`CommandHost.csproj` 引用了 `Dashboard.csproj`（为了拿 `PipelineRunner` 与 `PipelineDefinition`
——这两个类跟 HTTP 服务毫无关系，只是当初放错了程序集）。面板进程锁着自己的输出文件，
`dotnet run` 起命令宿主时 MSBuild 要先重编那条链，复制不动被锁的 exe，**整条命令以退出码 1 收场**。
裁决、批准、抽查、试跑、命令台，一个不剩。这从面板有按钮那天起就是坏的。
**已修**：`PanelCommandRunner` 起子进程时带 `--no-build`，并对「产物不在」这类失败给一句人能照做的话。
真正的修法是把那两个类挪出看板程序集、断掉这条引用——那是另一批的事，记在缺口里。

**② 五个 driver 里有两个的试跑命令根本不在白名单**（命令名以 `art.` 开头，
放行族只有 task. / pool. / bridge. / engine. / conflict. / spec. 六个）。点了必然被拒。
**已修**：放行族由 `CreationPanelPage` 从 `PanelCommandWhitelist` 装配进页面（真相仍只有 C# 那一份），
面板渲染时就判一次，跑不了的按钮给灰的并写明「不在放行族里，要么改自述、要么扩白名单」——
**扩不扩白名单是人的决定，面板不替人做**。

**③ 一个 driver 的试跑命令本身就缺必填参数**，点下去退出码 2，报缺 `RequirementIdentifier` 与 `DiffPath`。
这是 driver 自述的内容，不在这一批的改动面里，没动。

**④ 最重的一条：一个叫「试跑」的按钮，跑的是真的。**
某 driver 自述里写的是 `--dry-run`，而参数名实际是 `DryRun`。**对不上的参数被静默忽略**
（拿一个瞎编的参数名验过：照样退出码 0，没有任何一句话提示），于是干跑标志没生效，
输出里明明白白写着「干跑=否」——那次点击执行了一次真的供给。
所幸供给是幂等的，产物哈希一字未变，只有指纹里的生成时间戳动了一下，**已 `git checkout` 还原**。
但同一个坑还长在别处：`bridge.model` 的 Summary 自己就教人写 `--dry-run`，
而那条命令的真参数也是 `DryRun`——**照着它的说明写，会真发、花积分**。
这三处（driver 自述、命令 Summary、命令框架对未知参数的静默）都不在这一批的改动面里，已转给相关方。

**⑤ 补记：命令台那五条「常用命令」里有一条是假的。**
逐条走面板真跑之后，`spec.list` 报「未找到命令」——**`spec.` 这一族至今一条命令都没有**，
而白名单偏偏放行着它。写死一份清单就得跟真清单对过账，不然它就是五个陷阱。
已换成 `engine.mode --RepositoryRoot .`（留空 Mode 只显示不切换），五条现在全部真跑通过。
白名单里那个空族**没动**：收窄放行范围是安全边界的决定，该由人来做。

面板另外三条写命令（裁决 / 批准 / 抽查）的参数名**静态核对过**，
`ConflictIdentifier`·`ResolverName`·`Choice`、`ProposalIdentifier`·`Action`·`DeciderName`、
`LedgerIdentifier`·`Conclusion` 与命令宿主的参数类一字不差。
没真跑——它们改的是池子里的真数据，参数名对不对是静态判得出来的，不必拿真数据去试。

## 六、已知缺口

- **像素级观感 Claude 自己没看见。** 内置浏览器窗格截图不可用、Chrome 扩展没连上，
  这一批的「美观」只验到了结构层（布局无溢出、主题变量生效、对比度取自 Catppuccin 两套官方色板），
  **没有一张截图**。这一条必须由人开一眼确认——写在这里免得它被当成已验。
- **裁决 / 批准 / 抽查三个按钮仍然没真点过。** 试跑点过了（见第四节），
  通路上那个致命问题（面板一跑起来命令就编译不过）也已经修掉，所以这三个按钮现在
  **应该**能跑——但「应该」不算数，它们改的是池子里的真数据，这一批没找到安全的对象去点。
- **`bridge.model` 那条试跑没点。** 它标着花积分，用户明确说过这个 driver 的额度要单独买。
  参数名对不对得上（见第四节 ④）在它身上正好是花钱与不花钱的差别，**更不能拿真钱去试**。
- **门禁页在真仓库里恒为「未跑」，而且跑门禁也不会让它有数。**
  `_Generated/门禁报告.json` **至今没有生产者**——`gate.ps1` 只往控制台打、不落文件
  （P1 批次 5 就记下了这条，至今没销）。这一批给门禁页做的 KPI 卡、逐道方块阵、提示态，
  全是给一份不存在的数据做的展示：有生产者的那天就能用，在那之前它是十六页里唯一一页恒空的。
  **顺带改掉了我自己写的一句假话**：原文案是「跑一次 gate.ps1 再回来看」——跑了也不会有。
  现在如实写「这一页现在拿不到数据，而且跑门禁也不会让它有」，并说清缺的是生产者那一侧。
- **下游页那句「要改配置直接编辑 …」里的路径是第二个来源。** 真相在
  `CreationPanelReader.LocalConfigFilePath`，而页面文案自己又写了一遍——去中文化那批改目录名时，
  这句当场把人指向一个不存在的目录（原文是 `Config/创作管线/`，已跟着改成
  `Tools/CreationPipeline/Config/local.json`）。**该由后端把路径随数据一起给过来**，
  那要动 `PanelBridgeRow` 的形状；去中文化几批正在改同一个文件，等尘埃落定再收。
- **面板的 API 契约（前端读的 JSON 键 ↔ 后端 `JsonPropertyName`）没有任何测试保护。**
  这条是真咬过一次才发现的：并发那阵子，工作区里一度出现把 `[JsonPropertyName("预览")]`
  改成 `"preview"` 的改动（155 个键里唯一被改的一个，明显是批量替换误伤），
  而前端读的是 `行['预览']`——后果是资产页「有预览图」恒为 0、「预览」列恒显示「无」，**不报错**。
  **112 项测试当时全过**，因为它们断言的是 C# 属性，不是 JSON 键名。
  想补一道自动检查，两条路都不通：双向比对键名要维护一份例外清单
  （`/cmd` 的键、前端自造的对象键、正则误匹配），**清单本身会腐烂**；
  「键一律中文」又不成立——决策 1 明说 JSON 键不受 ASCII 约束，实际也有 `id`、`driver` 这类英文键。
  暂时没有不腐烂的自动化办法，记在这里。
- **白名单里 `spec.` 是个空族**——放行着一个至今没有任何命令的族。没动：收窄放行范围是安全边界的决定。
- 命令宿主对未知参数静默忽略、以及 driver 自述与命令 Summary 的写法，**都已由命令层那批修掉并提交**
  （参数认不出来现在当错误报，并列出这条命令认的全部参数名；五个 driver 的试跑命令也全部对齐了）。
  本批次日志第四节留着不删——它记的是「怎么发现的」，那比「修了」更值钱。
- 命令台的「常用命令」是写死的五条，没跟命令宿主的真实清单对账——名字打错了要跑一次才知道。

## 补：默认改成亮色，顺手修了两处配色缺陷

用户看完第一句话是「太黑了，换个白天的」。改默认主题只是一行，但真去量了一遍，
量出两处**写的时候没验、看着没事**的缺陷：

**① 亮色的层级方向是反的。** 亮色调色板是照着暗色的层级抄的——暗色里「越暗越靠后」，
所以卡片(`--层1`)比页面底(`--底`)暗。照搬到亮色，就成了 `--层1 #e6e9ef` 比 `--底 #eff1f5` 还暗：
**卡片陷进页面里**。亮色里该反过来，卡片是白的、浮在浅灰底上。已改成
`--层1 #ffffff` / `--层2 #e9ecf2` / `--面 #f6f7f9`。

**② 两套主题的 `--字弱` 都不达 WCAG AA。** 实测对比度：亮色 `#8c8fa1` 只有 **2.83**、
暗色 `#6c7086` 只有 **3.36**，而 AA 对正文要求 4.5——**大量说明文字、脚注、面包屑、
侧栏组名用的正是它**。改成亮 `#66697f` / 暗 `#8b90a8` 之后：

| | 大数字 | 卡片标签 | 脚注 | 弱字 / 面包屑 |
|---|---|---|---|---|
| 亮色 | 7.99 | 6.25 | 5.40 | **4.77** |
| 暗色 | 12.14 | — | 5.56 | **5.20** |

**暗色那条尤其值得记：它一直不达标，只是没人抱怨过。** 用户嫌黑才让我去量，
量的时候顺带把两套都量了——**只修被投诉的那一套，等于把同一个缺陷留一半在原地。**

对比度是量出来的，不是看出来的：这一批我自始至终没有截图通道，
但对比度、层级方向、有没有横向溢出这些**能算的东西不需要眼睛**。
真正需要眼睛的（好不好看、挤不挤、字号舒不舒服）仍然没验，还是那条缺口。

## 附：怎么才算一次可信的绿

这一批全程与另一个会话并发改同一个工作区，**门禁连着跑出三种互相矛盾的结果**：
全门禁红（连 `dotnet build` 都红，而单独跑是 0 错）、只剩两道红、只剩测试基线锁红
——而单独跑 `gate.baseline` 是 0 问题。**整编排红、单跑绿，只能是时序**：两边抢 `obj/bin`。
期间还抓到过 `git add` 与 `git commit` 之间的几百毫秒窗口；更早一次是对方正在实时编辑
`CreationPanelReader.cs`，我 grep 到的常量与 `git diff` 到的**不是同一个版本**，
据此差点发出一份错的 bug 报告。

**教训：在别人实时编辑期间跑出来的门禁结果不是结论，是快照。**
最后那次绿是跟对方要了一个静止窗口取的，**跑前跑后各记一次 `HEAD` 与
`git status --porcelain` 哈希，三者一致才认**（`a83a70e` / `5391e9408e8c`，PASS 全绿）。
共享工作区里，**「跑过了，绿的」这句话本身不完整**——得带上「跑的时候工作区是静止的」。
