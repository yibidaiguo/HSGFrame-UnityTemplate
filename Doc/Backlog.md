# 待办账本

> 已经想清楚、但**现在做不了或刻意不做**的事。每条要写足三样：**为什么值得做、
> 影响面多大、动手前要先解决什么**。没有这三样的条目不许进这份表——那种叫愿望，不叫待办。
>
> 实际项目里踩到的问题写[BUG 反馈簿](Bugs.md)，不写这里；同类 BUG 攒够次数再晋升成这里的一条。
> 做完的条目直接删——完成的理由与踩过的坑该进[踩坑清单](pitfalls.md)或提交信息，不在这里养历史。

## 卡在外部的（我做不了，等条件到位）

### 1. 飞书表格记录变更事件

**为什么值得做**：策划在多维表格里改需求，引擎现在收不到——只能靠助手对话或手动 `pool.pull`。
这是「策划在自己的工具里干活、机器自动跟上」这条主线的最后一段。

**影响面**：只差订阅那一步，代码零改动。链路其余部分（长连接、事件落盘、入站、去重）都真跑通过。

**卡在**：**你**——应用在那张多维表格上的权限要从「可编辑」提到「可管理」。
订阅云文档事件的接口只认文档拥有者与管理者，现在真调会回 `1069603 forbidden`（实测过）。
点法见[用户配置说明](creation-pipeline-user-setup.md)第三节第 4 点。提完权跟我说，我重跑一次订阅接口补验。

### 2. 策划文档推知识库：链路已通，差那个节点的编辑权

**为什么值得做**：`doc.push` 已经落地——拆块、幂等判定、整篇换掉、同步块回写、
错误诊断全都写完并跑过干跑；差的只是最后那一次真写。策划在飞书上看策划文档这件事，
现在只差一次授权就成立。

**影响面**：**代码零改动**。链路每一段都真跑过：命令 → 域路由（策划文档端 → feishu）→ 桥 →
中性块 → docx 块 → 真发 HTTP，一路走到飞书那道门前，回的是
`131006 permission denied: node permission denied, tenant needs edit permission`（实测过）。
权限一到位，同一条命令 `--dry-run false` 就该建出节点来。

**卡在**：**你**——应用现在对那个父节点只有读，没有写。
实测三条：`wiki/v2/spaces/get_node` 读得到（title=首页）、列子节点读得到、建节点回 131006。
点法：飞书里打开 `策划文档父节点` 那个节点 →「···」→ 添加文档协作者 → 搜应用名 → 给「可编辑」。
（空间级那条路也行：知识空间设置 → 成员 → 加应用给编辑权，但那是把整个空间放开，没必要。）
授完权跟我说，我重跑一次 `doc.push --dry-run false` 补验。

**顺带一提**：媒体块也卡在同一处。规范第四节说图片要转 docx 图片块，
那要走「上传素材 → 建 image 块 → 挂进去」三步，吃的是同一份编辑权限。
在那之前媒体降级成一行带路径与说明的文字（`FeishuBlockCodec.MediaLine`），
不静默丢掉。权限到位后连这一段一起补，那时才谈得上真跑过。

### 3. tripo 真出模型 + 模型链路端到端

**为什么值得做**：粗模 → 加工 → 机检这条链是美术自动化的下半程；现在只有上半程（出图）真跑过。

**影响面**：`bridge.model --DryRun false` 一条命令的事，**代码一个字不用改**（v3 已翻新并干跑验过）。

**卡在**：**你**——要在开发者门户单独买 **API credits**。实测三个事实：网页控制台显示有积分、
两个版本的余额接口都回 0、真提交一律 `2010 积分不足`。结论：Tripo Studio 的订阅积分与 API credits 是两套额度。

### 4. 多项目并行 + 一个飞书应用管多个项目

**为什么值得做**：目标形态是「一套框架管多个项目，各挂各的知识库」。现在仓库级隔离已经做实
（生成不带密钥、影子拷贝按仓库分目录、门禁临时文件带进程号、Unity 版本各自跟工程走），
**只差飞书这一层**。

**影响面**：当前安全形态是「一个飞书应用同时只有一个项目开着助手」；要两个项目都常驻，
就各建一个飞书应用。真做要动：项目标识进配置、旁路按 base 过滤事件、表名带项目前缀或一项目一 base 立成约定、
远期改成「一 App 一中枢旁路 → 分发到多仓库」。

**动手前要先解决**：① 第 1 条的提权（否则表格事件这条路本身就不通）；
② **双 base 的真实事件行为要真测**——两条长连接是分裂投递还是重复投递，决定中枢形态。
决策 91：没真跑过的不写。

### 5. 助手 A 形态：配置包程序化导入

**为什么值得做**：现在助手知识包（system-prompt + 5 份知识文件）要人手动贴进飞书后台，
指纹一变就得重贴一遍。程序化导入能把这一步并进 `bridge.provision`。

**影响面**：只影响「换知识后的同步成本」，不影响功能——助手 B 形态（常驻会话）已经真跑通。

**卡在**：外部平台到底开不开放这个接口，P1 批次 6 的 spike 结论至今没变（未验证）。
真要推进得先去查平台文档，查到了才谈实现。

## 等你拍板的（是策略不是活）

### 6. 面板命令白名单的两处收放

`art.` 族（能力对账）不在白名单，本地形态 driver 的对账在面板上点不了；`spec.` 是个**空族**
（至今零命令）却放行着。两件都是**安全边界**，该由你定：要不要放 `art.` 进去、要不要把 `spec.` 收窄。
**影响面**：各一行配置（`PanelCommandWhitelist.AllowedPrefixes`）+ 一条测试。

### 7. 资产名归一化器仍产中文名

`AssetInboxArchiver` 把带中文的图片名归一成**中文名**，且有测试锁住那个行为，
与 `gate.pathascii`（block 模式）直接打架——真走一次资产归档就会撞门禁。
**两条路二选一**：归一化器也转 ASCII（要一套音译或翻译规则，规则本身是设计决策），
或给它开豁免（那等于在全仓 ASCII 之外开一个口子）。**动手前要你选一条。**

## 技术债（自己能做，排在功能后面）

### 8. `PipelineRunner` 放错程序集

**为什么值得做**：`CommandHost.csproj` 反向引用 `Dashboard.csproj`，只为拿
`PipelineRunner` / `PipelineDefinition` 这两个跟 HTTP 毫无关系的类。后果是面板一跑起来
锁住自己的 exe，命令宿主整条链编不过——**面板上每个按钮从有那天起都是坏的**，
现在靠 `--no-build` 绕过（代价：跑的是上一次编译的产物）。
**影响面**：把两个类挪进 `Tools/Pipelines/` 之类的新程序集，改三处引用。
**动手前要先解决**：确认没有别的地方按 `Toolkit.Dashboard` 这个程序集名反射取它们。

### 9. 前后端中文键契约零测试保护

**为什么值得做**：面板前端读 `行['预览']`，后端是 `[JsonPropertyName("预览")]`。
曾被批量替换误伤成 `"preview"`，结果整列恒显「无」而**不报错、测试全绿**。
**影响面**：一条正则级对账测试（扫 Reader 的 `JsonPropertyName` 集合 vs panel.js 里的 `行['…']` 引用）。
**动手前要先解决**：panel.js 里有动态拼键的地方，要先确认哪些能静态扫出来——扫不全的部分要写清，
别让这条测试变成「看着有保护其实有洞」。

### 10. 逻辑层测试薄

**为什么值得做**：1500+ 纯 C# 测试里只有 40 多条在测游戏逻辑，其余在测工具链与门禁自身。
作为模板，被验证得最充分的是脚手架而不是游戏部分——**基于它做真项目的人没有测试范例可抄**。
**影响面**：不是补测试数量的问题，是要在 `Modules/` 下立一个「模块该怎么测」的范例
（Combat 三个文件是最小可用的样板位）。
**动手前要先解决**：等第一个真业务模块落地——拿真模块立范例，比给示例模块补测试有用。

### 11. 生效规范合并器

**为什么值得做**：子文档 07 设计的「三层就近合并 → `_Generated/EffectiveSpecifications/`」至今没实现。
G 批做的是**按 diff 裁剪**（治标，已生效），合并器才是设计里的正路——
还能顺带把「生效规范幂等」这道门禁真正立起来。
**影响面**：一个合并器 + 一道幂等门禁；预审提示词改读合并产物（那条回落分支早就写好了）。
**动手前要先解决**：三层合并的冲突语义（收紧任意 / 放宽仅限标了「可覆盖」的键）要逐类型定死，
这部分是设计决策，得走设计审查。

### 12. 每轮一个运行目录，起服务不用先停

**为什么值得做**：影子拷贝解决了「常驻进程占住 `bin/`」，但**影子目录自己**照样会被
上一轮起的常驻进程占着（助手就从 `HSGFrameRun/<项目>/commandhost` 里跑，一开就是一整天）。
现在的做法是快速失败 + 点名是谁 + 只镜像这一轮要起的那份（见 [BUG-0001](Bugs.md)），
够用但不彻底：换助手的新产物，仍然得先把助手停了。
**影响面**：每轮拷进 `HSGFrameRun/<项目>/<服务>-<版本记号>/`，PID 文件记住这一轮用的是哪个目录；
`stop.ps1` 照 PID 文件停；再加一步「删掉没有任何活进程引用的旧目录」。
**动手前要先解决**：旧目录什么时候删得干净——机器断电、进程被强杀之后 PID 文件会过期，
删除判据得只认「有没有活进程在用」，不能只认 PID 文件，否则要么删掉在用的、要么越攒越多。
