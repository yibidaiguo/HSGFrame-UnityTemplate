## 这一批真正做的是什么

P4 批次 2 做了 `PromotionProposalBuilder`——能从意见库**算出**提案。
但那份提案**只出现在命令输出里**：没落文件、没有状态、没人能批。
子文档 03「沉淀闭环」那句「能代码化进检查器（硬红），能提示词化进预审规则」，
从提案到那两个落点之间是空的。这一批把这段补上。

链路现在是完整的一条：**意见库 → 算提案 → 入库 → 批准 → 落成产物**。

## 幂等为什么只挡「未关闭」，不挡终态

入库要幂等，否则每跑一次 `task.promotion` 就多一条一样的提案。
自然的写法是「同类别已有提案就跳过」——**那是错的**。

同一类问题**再犯就该再提一次**。把 `已拒绝` / `已落地` 也当成挡板，
会让沉淀闭环卡死在第一次裁决上：拒过一次的问题，以后永远提不起来了。

所以挡板只有 `待批` 与 `已批准` 两个状态（合起来叫「未关闭」）。
**验收时真跑过**：`PR-0001` 落地之后同类再入库，成功开出新的一条。

## 落地不改状态，改状态在命令层

`PromotionLandingPlanner.Land` **只产产物，一个字都不改提案状态**。
把状态改成 `已落地` 是 `task.promotion.decide` 干的，而且**先产物、后状态**。

理由：产物写成了但状态没跟上，是「跑一次就好」的问题；
状态先跳到 `已落地` 而产物没写，是**账上说做完了、盘上什么都没有**——
而 `已落地` 是终态，改不回去，这笔账就永远查不清了。

**未关闭不判红**——待批提案是待办不是违规（与决策 51 同理）。
