# P8 批次 8 · 面板下游页：让它真能当装机清单用

> 上游：[创作管线P8计划](../creation-pipeline-p8-plan.md)。
> 这一批的两个问题**全是「真开一次面板」才发现的**——决策 76、79 那条纪律的又一次兑现。

## 一、真开面板发现的两个问题

子文档 05 §五 最后一句定义了下游页的职责：
**「执行机迁移：新机器照面板「下游」页红点逐项填绿即完成」**。

Claude 真开了一次，发现它做不到：

| 问题 | 现象 |
|---|---|
| **非密钥字段全空白** | `可执行文件：` `地址：` `应用标识：` 后面什么都没有，而 `本机.json` 里全配好了。**看不出这台机器到底配没配**，红点填绿无从谈起 |
| **探测路径没人写** | 面板去找一个规范路径，而 `bridge.probe` 的 `OutputPath` 是必填、指哪写哪。**那个路径上永远不会有文件**——决策 79 原话的翻版 |

**编译、测试、全量门禁当时全是绿的。** 这两条只有真看才看得见。

## 二、改法

- **非密钥字段也报「已配 / 未配」**，读 `本机.json` 的 `下游配置.<driver>.<字段名>`，
  判「在不在且非空串」。
  **不显示值**——理由不是保密，是**一致性**：这一页的语义是「配没配」，
  不是「配了什么」。混着显示会让人以为密钥那栏也只是省略了值，
  而密钥是**永远不读**（决策 78）。
- **「本机.json 不存在」与「文件有但这项没填」分成两支**（决策 42、77），
  前者额外给一行说明。
- `bridge.probe` 的 `OutputPath` 改成选填，默认写规范路径，自动建目录。

## 三、验收时 Claude 自己修的一处回归

执行端交回来时 `gate.provision` 是红的，它报「**既有状态，非本批引入**」。
**这个说法不成立**——这批之前 Claude 亲自跑过 `gate.ps1` 是 PASS。

根因：**探测结果被写进了 `_Generated/Bridges/<driver>/`，而那是供给产物的地盘。**
`gate.provision` 靠「那个目录在不在」判断该 driver 声称已供给，
探测结果一写进去，它就被当成「已供给却缺 11 个产物」判红。

这两样本来就是**反方向**的东西：

| | 方向 | 进 git 吗 |
|---|---|---|
| 供给产物 `_Generated/Bridges/` | 我们**推给**下游 | **进**（决策 12，对账要） |
| 探测结果 `_Generated/Probes/` | 从下游**读回来** | **不进**（跟机器走） |

所以分成两个目录，`_Generated/Probes/` 补进 `.gitignore`。
改完 `gate.provision` 回绿，面板照样找得到（两边共用同一个路径函数）。

**教训：交回来的「这不是我弄的」要自己核一遍。**
这批之前的全量门禁是绿的，这个事实就足以推翻那句话。

## 四、门禁抓到了 Claude 自己

修那处回归时，Claude 在注释里写了一个 driver 名解释来龙去脉，
**下游边界门禁当场判红**：`ProvisionPaths.cs:55 引擎代码里出现了下游 driver 名`。

有点讽刺：决策 93 刚写完「这道门禁只能拦住最蠢的那种越界」，
转头就被它拦了一次——而且拦对了。**注释也是代码的一部分，一样受这条边界管。**
改成不点名，全绿。
