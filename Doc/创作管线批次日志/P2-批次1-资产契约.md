## 这一批真正做的是什么

P2 是生图链路，但它的一半挂在 ComfyUI 上——那东西没装、没跑过，按锁定决策 23
不给它写桩。**这一批做的是完全离线、完全能真验的那一半**：资产请求与溯源边车的契约、
一个吃任意实体 schema 的通用文档校验器、两条命令。

生图 driver 一行没写。写了也只能是没跑过的桩。

## 实际落地

**两份基线契约**（Claude 直接落盘，属设计不外派）

- `Pools/Schema/基线/资产请求.schema.json`：15 字段，id 模式 `^ASSET-\d{4}-\d{2}$`，
  形状照子文档 06 §一那段 JSON。
- `Pools/Schema/基线/溯源.schema.json`：13 字段，含 `随机种` / `配方` / `提示词` / `文件哈希` /
  `当选`——子文档 06 §七 要的「边车齐全 ⇒ 任何历史资产可复现」全靠这几个字段。

**引擎与命令**（派活）

- `AssetPaths`：资产请求 / 变体 / 人工变体 / 边车 / 弃 / 预览六族路径。
- `EntityDocumentValidator`：**本批的核心**。吃任意 `PoolSchema`，十条判定规则，
  文案一律复用 `ValidationMessageCatalog` 里 `需求.` 那一族——那些文案是**字段级**的、
  与实体无关，为资产另造一族只会让 `校验错误文案.json` 里多出一堆重复的话。
- `AssetRequest`：模型 + 读写 + 取号（`ASSET-<需求四位>-<该需求下序号 +1>`）。
- `ProvenanceSidecar`：模型 + 读写 + `ComputeFileHash` + `ForManualProduction`
  （人产物一放进来 `当选` 就是 true——子文档 06 §二 第 6 步「人改即权威」）。
- `Tools/Cli/CommandHost/Commands/ArtCommands.cs`：`art.request` / `art.validate`。

**`.gitignore`**：变体本体不进仓库，边车进（子文档 06 §二 第 8 步，算力换体积）。
三条规则，目录必须单独放行否则 git 不往里走。

## 本批新增的锁定决策

24. **通用文档校验器复用 `需求.` 那一族规则 id，不给每个实体另造一族。**
    那些文案是字段级的、与实体无关；另造 = 两张皮。
25. **命令族用 `art.*`，不用 `asset.*`。** `asset.validate` 已被 Unity 资产管线
    （`Tools/Cli/CommandHost/Commands/AssetCommands.cs`）占用，而
    `CommandRegistry.ScanAssemblies` 遇到重名**直接抛异常、整个命令宿主起不来**。
    `art.*` 也正是子文档 06 的命令族（`art.generate` / `art.import` / `art.explore` / `art.regenerate`）。
26. **变体本体 gitignore，边车全部进 git。** 变体可由边车重生成。
    规则要写成「排除 `变体/**` + 放行 `变体/**/` 目录 + 放行 `**/*.溯源.json`」三条——
    只写排除的话 git 根本不会走进那棵子树，边车也就跟着丢了。

## 执行后端这一轮报上来的三件事（都属实）

1. **`asset.validate` 命令名冲突**——见锁定决策 25。它自己查到 `CommandRegistry` 遇重名会抛，
   改了名并**明确请派活方复核**，没有偷偷改既有文件。这是对的做法。
2. **`GateCommandSupport.ToResult` 吃的是 `GateFinding` 不是 `PoolFinding`**，
   任务书让它「直接用」是我写错了。它写了个等价的私有转换，没复制那个类。
3. **`PoolTestWorkspace` 没有「写真实基线 schema」的方法**，它从仓库读真实文件写进临时池子，
   没改夹具。
