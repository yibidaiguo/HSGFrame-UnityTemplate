# 创作管线 · P6 批次 2「重规划落地」日志

> 总账在 [创作管线进度](../creation-pipeline-progress.md)。本文只装这一批的落地记录与验收证据。

## 这一批真正做的是什么

子文档 03 §四的打断重规划算法有五步。P4 批次 1 做完了第 1–3 步——那就是
`ReplanPlanner`：算出谁脏、谁净、谁要后端评估、哪些人改权威文件落在脏集里。

**但它只出一份计划，一个字都不落盘。** 没人把脏项真的标脏，没有新基准，没有回方案关。
这一批把第 4、5 步补上：**快照成新基准 → 脏项标脏、净项保留 → 回方案关**。

## 三道拒绝闸，命中就一个字都不写

落地器 `ReplanLanding.Apply` 先过三道闸，任何一道命中**磁盘零变化**：

1. **零脏项** —— 不需要落地。走 Success，不是错误。
2. **有工作项还在「执行中」** —— 子文档 03 §四第 1 步是「当前原子步骤跑完即停」；
   还在跑就落地，会把正在写的产物和标脏撞在一起。
3. **脏集里有人改权威文件且人没确认** —— 停下问人（第 5 步的原话）。
   带确认标志时照常落地，但**必须往发现里加一条「人已确认」**——确认过也要留痕。

「写一半再拒」是这三道闸最需要防的失败：半落地的重规划比没落地糟，
因为下次跑会以为已经重规划过了。

## 净项的「保留」是一个字都不改

不是给净项写一个「净」状态。**给没有任何变化的东西留下一次写入，
下次人改检测（子文档 03 §三：现 hash ≠ 登记值即判人改）会把它误判成人改**，
从此引擎再也不重写那个文件。`KeptClean` 只是把名单抄出来给人看，
落地器一个净项文件都不打开写。

## 先证据、后状态

顺序写死：**快照 + `05-change-impact.md` 全部写完，才动工作项状态与 `状态.json`。**

快照写成了而状态没改，是「再跑一次就好」；状态先跳到「停在关卡·方案」而快照没写，
是**回了方案关却没有新基准可审**——人打开面板看到要审方案，
却不知道审的是哪一版需求。与决策 63 同一条道理。

`状态.json` 读不出来时**不凭空造一份**：记一条发现说阶段没改，
但快照与标脏照样算数（它们已经写成了）。

## 落地

**数据**：`_Tasks/<需求id>/00-requirement.v<N>.json`（新基准，逐字节原文，既有版本永不覆盖）、
`_Tasks/<需求id>/05-change-impact.md`（六个小节恒在，没内容写「无」，每次落地整份重写）。

**引擎**：`RequirementSnapshot` + `RequirementSnapshotStore`（取版次 / 逐字节落盘）、
`ReplanLanding`（三道闸 → 证据 → 状态）。
**`ReplanPlanner.cs` 一个字没改**——它是纯计算器（决策 52），落地是新类的事。

**命令**：`task.replan` 加 `Apply` / `HumanConfirmed` / `RequirementFile` 三个参数。
**不带 `Apply` 时输出与改造前逐行一致**——老行为一个字没动。

**门禁**：不新增。

## 执行后端这一轮报上来的

1. **没加中文参数别名**——**它是对的**。任务书里我照惯例写了「中文别名按决策 57 一并给」，
   但它引用了进度文档第三节刚补的那条：`--arguments-file` 的键只认 ASCII 属性名，
   `[JsonPropertyName]` 会被默认值填充覆盖。**P6 批次 1 踩的坑，批次 2 就没再踩**——
   把坑写进文档这件事当场回本了。
2. **「新版次文件已存在时抛」这个分支单线程不可达**：`CurrentVersion` 扫最大 N、
   新版次 N+1，v(N+1) 存在则 `CurrentVersion` 就已经 ≥ N+1。它照任务书给的后门
   改成直接预置 v1/v3/v4 验「写 v5 且 v4 一字未变」，抛错代码保留给并发用。
   判断正确——为了凑一条测试去改实现才是错的。
3. 两份新测试要登记进 `test-baseline.json`，由 Claude 补，已补。
4. 它的临时目录 `rm` 被沙箱拒了，落在系统临时目录，不影响仓库。
