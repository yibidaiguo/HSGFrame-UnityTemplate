# 池子与需求模型(创作管线子文档 01)

> 上游:《策划美术工作流接入方案》§一–§三。本文定文件格式与数据规则,不重复讲理念。

## 一、目录与命名

```
Pools/
  Schema/
    基线/requirement.schema.json | work-item.schema.json | design-record.schema.json | 定稿.schema.json | provenance.schema.json
    项目/requirement.extension.json            ← 项目业务字段(合并语义见子文档 07)
  Inbox/<渠道>-<记录id>-<修订>.json
  Requirements/REQ-0042.json
  专项/EP-0003.json
  组织/成员.json | 卡片路由.json
  审查意见/                        ← 终审打回意见库(只追加,喂预审与晋升)
  Designs/
    记录/DR-0107.json
    汇总/<模块>.md                 ← 生成物,不手改
    定稿/<名称>@v<N>/(final.json + 参考图/ + lora/)
    conflicts.json
  queue.json                        ← 已确认待执行的任务队列
```

- ID 规则:`REQ-` / `DR-` / `WI-` / `ASSET-` + 四位递增;取号 = 扫描现存最大号 +1(v1 单机串行无并发冲突;并行留 v2 改计数器)。
- 一需求一文件,文件名即 id;门禁查文件名与 `id` 字段一致。

## 二、需求骨架(基线 schema)

| 字段 | 类型 | 说明 | 所有权 |
|---|---|---|---|
| id | string | REQ-xxxx | 工程 |
| 类型 | enum | 系统/修改/缺陷(项目可扩) | 策划端,锁定后不可改 |
| 状态 | enum | 草稿/已确认/进行中/待验收/已完成/已作废 | 工程 |
| 来源 | object | {渠道, 记录id, 提交人, 提交时间} | 工程(入库时写) |
| 标题/描述 | string | — | 策划端 |
| 验收标准 | array | 至少 1 条,阶段 4 逐条核 | 策划端 |
| 分类型必填 | — | 系统:目标/玩法;修改:现状/期望;缺陷:复现步骤/期望/实际 | 策划端 |
| 关联设计记录 | array | DR-id;系统类型完成时门禁查非空 | 工程 |
| 父需求 / 依赖 | id / array | 拆分与排序 | 工程(方案阶段写) |
| 专项 | string | EP-xxxx,可空;定卡片路由与缺省锚点 | 策划端(提需求时挂载) |
| 锁定 | bool | 已确认置 true,内容字段冻结 | 工程 |
| schema版本 | string | 入库时的合并 schema 版本 | 工程 |
| 同步 | object | {最后同步hash, 时间} | 工程 |
| 冲突 | array | 关联冲突条目 id | 工程 |

业务字段与骨架并列存于同一 JSON,机器不读;`requirement.extension.json` 声明其名称/类型/是否渲染到表单与助手。

示例:

```json
{
  "id": "REQ-0042", "类型": "系统", "状态": "已确认",
  "标题": "七日签到", "描述": "……",
  "目标": "次留提升", "玩法": "……",
  "验收标准": ["登录弹出签到界面", "第7天发放大奖", "断签从第1天重计"],
  "来源": {"渠道": "feishu", "记录id": "recXXX", "提交人": "策划甲", "提交时间": "2026-08-18T10:00:00"},
  "关联设计记录": [], "父需求": null, "依赖": [],
  "锁定": true, "schema版本": "1.2.0",
  "同步": {"hash": "…", "时间": "…"}, "冲突": [],
  "优先级": "高"
}
```

## 三、类型 → 管线模板

管线模板是规则数据,走规范分层:基线 `Specifications/Baseline/管线模板.基线.json` 发默认三类型,项目加类型 = 项目层加一条映射。内容:类型名 → 阶段序列 + 关卡配置 + 快道阈值。引擎按名取模板,不识别类型语义。

```json
{
  "系统": {"阶段": ["方案", "执行", "集成", "终审"], "方案人审": true},
  "修改": {"阶段": ["评估", "执行", "集成", "终审"], "快道阈值": {"工作项数": 2}},
  "缺陷": {"阶段": ["复现", "修复", "回归", "终审"], "方案人审": false}
}
```

## 四、状态机与转换权限

| 转换 | 谁可以 | 触发 |
|---|---|---|
| 草稿 → 已确认 | 白名单确认人 | bitable/面板改状态 |
| 已确认 → 进行中 | 引擎 | 任务开跑 |
| 进行中 → 待验收 | 引擎 | 阶段 4 完成 |
| 待验收 → 已完成 | 引擎 | 双线终审通过、合并 |
| 待验收 → 进行中 | 引擎 | 策划验收打回(按变更走横切 A) |
| 任意 → 已作废 | 白名单 | 人工 |

非法转换一律拒绝并留痕(同步日志)。

## 五、工作项

```json
{
  "id": "WI-0042-03", "需求id": "REQ-0042",
  "域": "资产.生图", "标题": "签到金币袋图标",
  "状态": "待执行",
  "依赖": ["WI-0042-01"],
  "验收点": "图标进图集、界面上正常显示",
  "引用需求字段": ["玩法", "验收标准[1]"],
  "产物": [],
  "消耗": {"llm": 0, "生图": 0},
  "人工产出": false
}
```

- 状态:待执行 / 执行中 / 待审 / 完成 / 标脏 / 挂起。
- `引用需求字段` 供重规划的影响映射用(子文档 03 §四)。
- 域清单是数据(`Specifications/Project/域.json`):域名 → 子管线命令序列 + 门禁集;加新域不改引擎。

## 六、设计池文件

设计记录:

```json
{
  "id": "DR-0107", "模块": "签到",
  "决定": "断签后从第 1 天重新计数",
  "理由": "简化补签逻辑,首月不做补签",
  "关联需求": ["REQ-0042"],
  "作废": null,
  "作者": "引擎", "时间": "…"
}
```

- 只追加不改写;作废 = 在新记录里写 `"作废": "DR-0058"`,旧条目本体不动。
- 汇总生成:按模块分组取未作废记录、按时间序渲染 `汇总/<模块>.md`;幂等门禁重跑无 diff。
- final.json:色板(hex 数组)、参考图相对路径、负面清单、LoRA 引用、版本、生效日期。

冲突列表条目:

```json
{"id": "CF-0009", "旧": "DR-0058", "新": "REQ-0042", "发现阶段": "入库",
 "状态": "未决", "裁决": null}
```

裁决后:`"裁决": {"人": "…", "选择": "改旧的", "时间": "…"}`,状态=已裁决。
裁决动作走 `conflict.resolve CF-0009 --选择 改旧的`——面板冲突页按钮与卡片回调同走此命令。

## 七、专项(范围层)

```json
{
  "id": "EP-0003", "名称": "水下遗迹场景包",
  "目标": "……", "状态": "进行中",
  "创建人": "策划小A",
  "默认锚点": {"定稿": "水下遗迹风格@v1"},
  "认领": {"美术": ["open_id_B"], "程序": ["open_id_C"], "策划": ["open_id_A"]}
}
```

- 落点 `Pools/Epics/EP-xxxx.json`;状态:规划中 / 进行中 / 已完成 / 已归档。
- 制定归策划;认领归成员且**可跨默认职责**(显式认领;首次处理该专项卡片=隐式认领,仅限默认职责内);转手=改认领表。
- 认领字段 v1 经飞书专项表直接编辑、走既有同步通道对齐(零新接口);Web 面板认领留后期。
- 作用:卡片路由(子文档 03)、资产请求缺省锚点(子文档 06)、总览页进度汇总。**引擎执行不感知专项**。

组织文件(`Pools/Organization/`,协作层——结构随框架,内容归项目):

```json
// 成员.json 条目
{"open_id": "…", "姓名": "老C", "默认职责": ["程序"], "确认人": true}
```

`卡片路由.json`:卡片类型 → 职责映射(默认表随基线发,项目可改)。
