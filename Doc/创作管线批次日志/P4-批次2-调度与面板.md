## 为什么不写常驻 daemon

子文档 03 §五 说轮询模式要有个 `engine-daemon` 常驻定时扫队列。**本批不写那个进程**，
两条理由都不是偷懒：

1. **常驻进程在门禁里没法验**——它不退出，`dotnet test` 就挂在那儿。
   写一个「跑起来但没人验过它会不会卡死」的守护进程，正是锁定决策 23 反对的东西。
2. **唤醒模式的事件订阅要经需求编辑端 port**，而飞书 API 不在可验范围（决策 6）。

所以落的是**一次 tick 的全部判定逻辑**加**单实例锁**。
把 `engine.tick` 挂进计划任务或一个 `while` 脚本就是轮询模式，接到真事件上就是唤醒模式——
**循环本身是外壳，判定才是引擎。**

## Claude 在验收时补的三处

### 1. 任务图页的「标题」列恒空

执行后端把 `PanelDagNode.Title` 置了空串并**主动请我定夺**，理由是 `WorkItemNode` 没有
`Title` 字段，而我的红线写着「DAG 用 `WorkItemGraph`，不另写一份读取」（决策 21）。

**它的保守是对的，但这里应该补字段。** `WorkItemGraph.Load` 本来就在解析工作项 JSON
（旁边就是 `TryReadString(obj, "状态", ...)`），给共享读取器加一个 `标题` **正是「同源」**，
不是另开一份读取。已补 `WorkItemNode.Title` 并接到面板，加了断言锁住这条链路。

### 2. `SingleInstanceLock` 没有测试覆盖

它自己在实现阶段修过那里两处判活缺陷（`process != null` 恒真；查别的用户进程抛
`Win32Exception` 会冒泡打炸 `engine.tick`），却因为任务书的文件清单里没列而没写测试。
**改过 Bug 又没测试覆盖的代码最该补**——已补 `SingleInstanceLockTests`（5 条），
含「持有者活着时拒绝」与「陈旧锁接管」两条关键路径。

### 3. DAG 端点的中文查询串键会静默返回空数组

`/api/panel/dag` 的参数键是 `需求id`。**客户端不把它按 UTF-8 百分号编码，就认不出来**，
而认不出来时返回的是 `[]`——与「这个需求没有工作项」**一模一样**。
浏览器会自动编码所以页面本身没问题，但手敲的 curl 会静默拿到空结果。

这是决策 20（没有的东西不说成绿）那类问题的又一变种。已加 ASCII 别名 `requirement`，
两个键都收。

顺带清掉了 P3 遗留的 4 条 xUnit2031 警告——「0 警告」这条完成标准此前是假的。

## 本批新增的锁定决策

54. **不写常驻 daemon，只落一次 tick 的判定与单实例锁。** 理由见开头。
55. **陈旧锁必须能被接管。** 断电留下一把永远解不开的锁会让轮询模式再也起不来，
    那比偶尔多跑一个实例糟得多。锁文件读不动时同样按陈旧锁接管。
56. **值守压倒一切。** 值守 + 队列有活 + 唤醒信号，照样不取活（决策 10 的执行落点）。
    唤醒只跳过「间隔检查」，不跳过模式判定——处理逻辑与轮询同一条，防漏。
57. **对外接口的中文键要配 ASCII 别名。** 认不出参数和「查无此物」返回同一个空结果，
    是决策 42 的又一种长相。
