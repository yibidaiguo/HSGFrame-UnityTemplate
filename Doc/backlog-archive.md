## A. 文件名与目录名去中文化 —— 完成于 2026-08-21

**为什么值得做**：跨平台与工具链上，中文路径是一类**低频但很贵**的故障源——
git 在不同 `core.quotepath` 下显示不一致、CI 容器 locale 非 UTF-8 时路径会烂、
某些 .NET / MSBuild / Unity 的路径处理在非 ASCII 下有历史坑。本仓踩过近亲：
`gate.ps1` 输出重定向到文件时子进程 JSON 日志会丢（编码相关）。

**当时的影响面**：197 / 1240 个已跟踪文件带中文名、24 个中文目录，最大一块在
`UnityProject`（76 个，靠 GUID 引用所以 `.meta` 跟着挪就安全，但要真开 Unity 验）。

**落地**：设计审查见[路径去中文化](ascii-path-migration.md)，逐批记录见
[各批落地记录](ascii-path-migration-log.md)。新增门禁 `gate.pathascii`，
**存量 0 条、模式 block**，反向验证过（造一个中文名当场判红）。

**从此的规矩**：全仓目录名与文件名一律 ASCII；中文照旧留在**文件内容**里
（注释、文案、数据值、JSON 的键都不受限）。

**尾巴**：资产名归一化器（`AssetInboxArchiver`）仍把带中文的图片名归一成中文名，
且有测试锁住那个行为，与门禁打架——这条**未销**，见待办账本。

## B. `Config/` 分层：工具配置归位 —— 完成于 2026-08-21（与 A 合批）

**问题**：`Config/` 根下五个目录是**三种不同的东西**混在一层——业务数据（策划天天改）、
表格工具链（程序很少改）、创作管线机器配置（装机的人一次性）。而结构规范总纲 §四把
`Config/` 定义成「数据与定义（单一事实源侧）」，机器配置本来就不该在里面。

**为什么与 A 合批**：两件事都要挪 `Tools/CreationPipeline/Config/`、都要改 `.gitignore` 的密钥路径、
都要改路径常量与门禁配置。分两次做等于把同一批危险改动做两遍。

**落地**：`Config/` 现在只剩 `Tables/` `Schema/` `Mirror/` 三样业务数据；工具配置各自归位到
`Tools/<工具>/Config/`（跟 Gates / AssetPipeline / CodeGen / Indexing 四个既有惯例走，不发明新概念）。
**最危险那一步（`.gitignore` 里的密钥路径）验过**：`git check-ignore` 命中新路径，
`git status` 里没有 `local.json`。

## C. `bridge-tripo` 翻到 v3 —— 完成于 2026-08-21

**怎么发现的**：用户充值后 API 仍报 `2010 积分不足`，去查官方文档才发现**主机和大版本都不对**
（`api.tripo3d.ai/v2/openapi` → `openapi.tripo3d.ai/v3`，四个端点全变）。

**根因是 Claude 自己**：`local.example.json` 里那个 v2 的 base URL 是凭印象写的，
执行端照着任务书建的桥。

**教训（已立成决策 94，并写进任务书模板）**：**外部 API 的 base URL 与端点形状，
不许凭印象写进任务书。**本仓已为「不许凭印象」立过几条规矩（决策 31 不编版本号、
决策 88 依赖没下完不算绿、决策 91 只有真跑才算数），这次是同一个毛病换了个地方犯：
任务书里写了「你要拿真回包核对」，**但 base URL 本身没让核**。
下次写下游任务书，第一条要核的就是 base URL。

**另一个实测事实**：官方快速开始那页自己写错了模型名（写 `tripo-v3.1`，服务端当场拒）——
文档也不能全信，以真回包为准。

**尾巴**：代码通了但**真出模型未验**，卡在账号 API credits——见待办账本。

## D. 常驻服务锁住 bin 导致门禁全红 —— 完成于 2026-08-21

**现象**：面板或 `assist.serve` 开着时，`dotnet build` 一律 MSB3027/MSB3021 失败，
`gate.ps1` **整片全红**（每道静态检查都要 `dotnet run` 命令宿主，而它依赖被锁的程序集）。
那片红看着像自己的改动把仓库改崩了，实际跟改动毫无关系——排查时在这上面绕过一圈。

**落地**：`Tools/start.ps1` 编译一次后把产物**影子拷贝**到 `%LOCALAPPDATA%/HSGFrameRun/<仓库名>/`
再起服务，bin 从头到尾没人占；面板加 `--stop-file` 常驻模式（后台起服务没有可挂住的 stdin）。
实测：面板开着照样 `dotnet build` 全绿。`Tools/dispatch.ps1` 后来也照此办理——
派活一跑几分钟，期间执行端自己还要编译。

**从此的规矩**：起服务一律走 `Tools/start.ps1`。见到「being used by another process」，
大概率是有人绕开脚本手起了服务。
