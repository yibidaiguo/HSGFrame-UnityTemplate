# 模块要图：配方、规格、风格三样分开放

## 先分清这三样，分错了后面全乱

| 东西 | 住哪 | 改它要做什么 |
|---|---|---|
| **规格**：尺寸、格式、透明、落点、命名模式 | `Specifications/` 三层 asset-spec（基线 → 项目 → 业务） | 改一个 JSON 字段 |
| **风格**：画风、色调、负面清单、LoRA | 请求里的 `描述` + `风格锚点.定稿`，定稿在设计池 | 换锚点 / 升定稿版本 |
| **配方**：ComfyUI 的节点链本身 | `Bridges/comfyui/recipes/<名>@v<N>/` | 新建一份配方 |

**一句话判据：尺寸变了、风格变了，都不新建配方。只有节点链要变才新建。**

这条判据是这份技能存在的主要理由。一个模块一份配方会让配方目录爆炸，
而它们的 `workflow.json` 会 95% 雷同——雷同的东西有五份，改一处就得记得改五处。

## 一、先问：要不要新建配方

按顺序问，**任一条为「是」就停在那一步**：

1. **现有配方里有吃这个资产类型的吗？** `ls Bridges/comfyui/recipes/`，看每份 `mapping.json` 的「资产类型」。
   有 → 先假定复用它，往下走第 2 条。
2. **只是尺寸/落点/命名不同？** → **不新建**。走下面第二节，写业务层覆盖。
3. **只是画风不同？** → **不新建**。走第三节，换风格锚点或在 `描述` 里说清。
4. **生成方式变了吗**——文生图 ↔ 图生图、要不要参考图入口、要不要 LoRA、
   要不要透明底裁切这类额外节点？ → **这才需要新建配方**，走第四节。

判不出来时默认「不新建」。多一份配方的成本是永久的，改一次业务层覆盖的成本是一行。

## 二、尺寸、落点、命名：写业务层覆盖

模块自己的规格住 `Specifications/Business/<模块>/asset-spec.json`：

```json
{
  "版本": "1.0.0",
  "资产类型": {
    "图标": { "规格": { "宽": 512, "高": 512 }, "落点": "Assets/Game/ResourceArt/Icons/<模块>/" }
  }
}
```

三条规矩：

- **只能覆盖基线「可覆盖」清单里的键**，清单外的键覆盖了会被 `gate.assetspec` 判红。
  先看 `Specifications/Baseline/asset-spec.baseline.json` 里那个类型的「可覆盖」写了什么。
- 覆盖只许**收紧**不许放宽（数字变小、布尔 false→true 算收紧）。要放宽得先改基线的「可覆盖」。
- 出图时**必须带 `--Module <模块>`**，否则取不到这一层覆盖，出来的是基线尺寸——
  「按带业务层的数据建、拿不带业务层的数据校」是这条链路上最常见的一种自相矛盾。

## 三、风格：锚点与定稿，不写进配方

风格走请求里的 `风格锚点.定稿`，指向设计池里的定稿（色板 + 参考图 + 负面清单 + 可选 LoRA）。
缺省取所属专项的「默认锚点」——**同专项的资产因此自动风格一致，这是默认行为，别绕过它**。

- 只是这一张要特别一点：写进 `描述`，不动锚点。
- 整个模块要一套自己的调子：建一份新定稿，请求里显式指定锚点。
- 已入库资产跑没跑偏：`art.deviation`（只报告，不自动行动）。
- 要一份色板：`art.palette`。

细节看 `Doc/creation-pipeline-subdocs/06-art-pipeline.md` 第五节。

## 四、真要新建配方时

配方名用 `<用途>@v<N>`，全 ASCII（决策 1）。目录里两份文件缺一不可：

**`workflow.json`**：**不是 ComfyUI 导出的那份，是仓库自己的中文骨架。**
形状是 `节点id → {类型, 参数, 连线}`，`连线` 里写 `参数名: ["上游节点id", 输出下标]`：

```json
{
  "2": { "类型": "CLIPTextEncode", "参数": { "text": "" }, "连线": { "clip": ["1", 1] } },
  "3": { "类型": "EmptyLatentImage", "参数": { "width": 256, "height": 256, "batch_size": 1 } }
}
```

调用时 `WorkflowTranslator` 把它翻成下游 API 形状（`class_type` / `inputs`）。
在 ComfyUI 里搭好之后按这个形状**手抄一遍**，照 `icon@v5/workflow.json` 的样子写。
**连线指向不存在的节点是硬错误**——翻译器当场抛，绝不静默产一张断图。

**`mapping.json`**：把请求字段接到 workflow 的节点参数上。

```json
{
  "契约版本": "1.0.0",
  "配方名": "<用途>@v1",
  "资产类型": "图标",
  "映射": [
    { "请求字段": "描述",     "节点id": "2", "参数名": "text" },
    { "请求字段": "规格.宽",  "节点id": "3", "参数名": "width" },
    { "请求字段": "规格.高",  "节点id": "3", "参数名": "height" },
    { "请求字段": "变体数",   "节点id": "3", "参数名": "batch_size" },
    { "请求字段": "命名",     "节点id": "4", "参数名": "filename_prefix" }
  ],
  "锚点槽": [],
  "依赖": []
}
```

四条会被 `gate.recipe` 咬的规矩：

- **请求字段只许这几个**：`资产类型` `描述` `命名` `落点` `变体数` `域`，
  外加以 `规格.` 或 `风格锚点.` 开头的。别的名字一律判红。
- **节点 id 必须在 workflow.json 里真存在。**
- **「依赖」里写的每一样都要在 `Bridges/comfyui/dependencies.json` 里声明过**
  （自定义节点、底模、LoRA）。装机页与 `art.caps` 靠那份清单对账。
- **锚点槽只指向主链上的节点。** ComfyUI 不执行没被引用的节点——
  往一个游离的 `LoadImage` 上挂槽，接口在、语义不在，比没有更骗人（`icon@v5` 真踩过这条）。

建完当场验：

```bash
pwsh Tools/Gates/gate.ps1
```

## 五、出图

```bash
dotnet run --project Tools/Cli/CommandHost/CommandHost.csproj -- describe art.request
```

顺序固定：`art.request`（带 `--Module`、`--AssetType`）建请求 → `bridge.generate --Driver comfyui
--RecipeName <配方名> --RequestPath <请求 json>` 出变体 → `art.select` 选片 → `art.validate` 收口。
出模型资产多一步 `art.plan` / `art.modelcheck`。

## 六、两条出图路怎么选

| | 本地 ComfyUI 配方 | 中转生图节点 |
|---|---|---|
| 入口 | `bridge.generate --Driver comfyui` | ComfyUI 图里的「中转生图」节点，或 `--Driver oaiimage` |
| 出的图 | 进管线：有资产请求、变体、溯源边车、可复现 | **只是一张图**，不入库、不留边车 |
| 用在哪 | 要入库的正式资产 | 试风格、探构图、给人看一眼 |

**要入库的资产走配方那条路。** 中转那条快、但没有溯源边车，出来的图 `art.regenerate` 复现不了。
中转节点怎么装、怎么用，看 `Bridges/comfyui/scripts/relay_image_node/`。

## 红线

- 配方目录名、文件名全 ASCII（决策 1，`gate.pathascii` 是 block 模式、零豁免）。
- **不许把具体尺寸写进 `workflow.json`**：尺寸从请求经 `规格.宽`/`规格.高` 进来，
  写死在工作流里等于让业务层覆盖失效，而且失效得悄无声息。
- **不许为「这次想要 1024 而不是 512」新建一份配方。**
- 依赖没进 `dependencies.json` 就不算数：装机页会说「未验」，那是对的，别去改判据迁就它。
