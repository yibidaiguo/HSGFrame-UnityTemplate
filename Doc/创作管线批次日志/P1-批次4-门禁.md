# 创作管线 · P1 批次 4「门禁」日志

> 总账在 [创作管线进度](../创作管线进度.md)。本文只装这一批的落地记录与验收证据。

## 这一批真正做的是什么

子文档 07 §三·一列了**十一道**检查器，本批只做其中**五道**——剩下六道依赖的东西 P1 还没造：
设计义务要设计池汇总生成器、汇总幂等同上、资产规格要资产规格数据（P2）、
冲突可见要冲突列表闭环（P4）、生效规范幂等与基线未手改要 `规范/` 三层目录（尚未铺）。
提前写它们只能写成永远跳过的空壳。

**五道里只新写了三道。** 池子校验与扩展合法性直接调批次 1 就有的 `pool.validate` /
`schema.check`——再写一份检查器就是两张皮，正是子文档 02 反复警告的那种毛病。

## 实际落地

| 门禁 | 命令 | 判什么 | 逻辑落在哪 |
|---|---|---|---|
| 池子校验 | `pool.validate` | 需求文件过合并 schema、文件名 = id、分类型必填 | 批次 1 既有 |
| 扩展合法性 | `schema.check` | 项目层 schema 扩展没破坏骨架 | 批次 1 既有 |
| 供给对账 | `gate.provision` | 重算两个哈希与 `指纹.json` 比 | `ProvisionReconciler`（管线侧） |
| 下游边界 | `gate.bridgeboundary` | 引擎代码里不许出现 driver 名 | `BridgeBoundaryChecker`（门禁侧） |
| 层边界 | `gate.layerboundary` | 协作数据不许落 Unity 资产树、游戏代码不许引用池子 | `LayerBoundaryChecker`（门禁侧） |

五道全部接进 `Tools/Gates/gate.ps1`，插在「文档长度」与「生成物幂等」之间。
`gate.ps1` 的收尾文案从「十三道门禁全绿」改成「全部门禁全绿」——写死数字的文案每加一道就得改一次。

新增命令文件 `Tools/Cli/CommandHost/Commands/PipelineGateCommands.cs`；
`gate-config.json` 加两项：`bridgeBoundaryExemptions`（默认空）与
`collaborationDirectoryNames`（默认 `Pools` / `_Tasks` / `Bridges`）。

测试：`Gates.Tests` 118 条、`CreationPipeline.Tests` 117 条。

## 本批新增的锁定决策

15. **`Toolkit.Gates` 不许引用 `Toolkit.CreationPipeline`。** 门禁引擎不依赖管线引擎——
    需要管线知识的那道门禁（供给对账）把逻辑放管线侧，命令放命令层
    （`CommandHost` 两边都引用得到）。否则半个管线要在门禁工程里复制一遍。
16. **`collaborationDirectoryNames` 刻意不含 `_Generated`。**
    `UnityProject/Assets/Game/Scripts/View/_Generated` 是 UI 代码生成的合法落点，
    写进去会把既有产物一次判死。
17. **`bridgeBoundaryExemptions` 默认空，第一天就不破例。**
    下游边界门禁第一次跑就咬到了 `BridgeCommands.cs` 里那句「例如 `--driver feishu`」——
    处置是**改文案**（改成「值取 `Bridges/` 下的目录名」），不是加豁免。
    同样，`ProvisionReconciler` 的修复建议里原本要写 `Bridges/feishu/driver.json` 当参考路径，
    改成了 `Bridges/<名>/driver.json`。**这道门禁的价值全在于没有例外。**

## 执行后端这一轮报上来的两件事（都属实，已处置）

1. **`Tools/Gates/Config/` 在 `reasonix.toml` 的 deny 里**，执行后端改不了 `gate-config.json`。
   它只在代码侧做了缺省回退就交活并如实登记。两项默认值由 Claude 补进配置文件。
   **这条以后每次涉及门禁配置的派活都会撞上，任务书里就别把该文件列进「改哪些文件」了。**
2. **它发现了任务书自相矛盾**：任务书让 `ProvisionReconciler` 的参考路径写死
   `Bridges/feishu/driver.json`，而同一份任务书定义的下游边界门禁扫描根正好包含那个文件。
   它自己改成了 `Bridges/<名>/driver.json`。这是任务没写清，不是它写崩。
