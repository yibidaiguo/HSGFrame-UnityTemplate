# 创作管线 · 锁定的设计决策

> 创作管线的锁定决策 1–79（80 起在 [P8 那份](creation-pipeline-decisions-p8.md)，
> 99 起在 [需求文档那份](creation-pipeline-decisions-reqdoc.md)）。
> **改这里的任何一条都要重新走设计审查。**

1. **全仓路径一律 ASCII：目录名与文件名都不许有中文，中文只留在文件内容里**（注释、文案、数据值、JSON 的键都不受限）。2026-08-21 改过一次：原文只管「含 `.cs` 的目录」，还明说中文可以出现在文件名里；实测全仓有 206 个中文路径，而中文路径是一类低频但很贵的故障源（git quotepath、CI locale、MSBuild/Unity 的历史坑）。命名门禁的 `directoryNamePattern` 仍只作用于含 `.cs` 的目录，全仓那一道是新增的 `gate.pathascii`。
2. **工具链配置落 `Tools/<工具>/Config/`，`Config/` 只留业务数据**（`Tables` `Schema` `Mirror`）。2026-08-21 改过一次：原文写的是「落 `Tools/CreationPipeline/Config/`」，那是当年撞见「`Config/` 已被 Luban 占满」时开子目录绕过去的权宜。真正的规矩仓库里早就有——`Tools/Gates/Config/`、`Tools/AssetPipeline/Config/`、`Tools/CodeGen/Config/`、`Tools/Indexing/Config/` 四个工具都这么放，只有创作管线破了例。现在还这笔账，顺带回到总纲 §四给 `Config/` 的定义。
3. **schema 用自定义精简格式，不用标准 JSON Schema。** 标准 JSON Schema 表达不了「字段所有权」「锁定后可改」「状态机转换权限」这三样，而它们正是这套机器的核心。
4. **模板仓库零池子内容。** `Pools/` 下只铺空目录骨架（`.gitkeep`）与**基线 schema**；`Requirements/` `Inbox/` `专项/` `知识/` 一条真实数据都不许进。
5. **密钥永不入库。** `Tools/CreationPipeline/Config/local.json` 进 `.gitignore`，共享的 `downstream.json` 只存密钥**名**。
6. **飞书 API 不在可验范围。** driver 只落契约与离线产物，真调用留桩；任何声称「已连通飞书」的验收结论都不算数。
7. **幂等靠已入池需求的 `来源.修订`，不另立账本。** Inbox 文件处理后不删——留证据，靠幂等跳过。
8. **卡片路由的默认表是代码内建值**（`CardRouteTable.Default()`），`Pools/Organization/卡片路由.json` 存在才逐键覆盖。
9. **`提出人` 是伪职责**：先查成员表姓名，查不到退化成 `策划`，再走第②③④步。
10. **值守是默认模式**：`Tools/CreationPipeline/Config/engine.json` 缺失时返回值守——配置读不到时最安全的行为是永不自动。
11. **字段类型映射住 driver.json，不住 C#。** 供给引擎完全泛化，driver 名永远是参数——这是下游边界门禁能绿的前提。基线 schema 的类型是中文（`数组`/`对象`），映射表中英文键都要有。
12. **`_Generated/Bridges/` 的产物进 git。** 生成层按数据分层表本来就「进 git（对账）」；产物进库，供给对账门禁才有牙。
13. **指纹只比两个哈希，不比产物文件。** `生成时间` 不参与哈希与对账；指纹不存在判「未供给」= 跳过，不判红。
14. **「提出人」「管理员」是伪职责，不给认领列。** 专项表的认领列只有 `美术` / `程序` / `策划`。
15. **`Toolkit.Gates` 不许引用 `Toolkit.CreationPipeline`。** 门禁引擎不依赖管线引擎；需要管线知识的门禁把逻辑放管线侧、命令放命令层。
16. **`collaborationDirectoryNames` 不含 `_Generated`。** 那是 UI 代码生成的合法落点。
17. **`bridgeBoundaryExemptions` 默认空，不破例。** 下游边界门禁咬到自家文案时改文案，不加豁免——这道门禁的价值全在于没有例外。
18. **面板绑定地址钉死 `http://localhost:{Port}/`。** 面板能触发命令 = 能动仓库，不给开局域网的配置开关。
19. **`POST /cmd` 只放行 `task.` / `pool.` / `bridge.` / `engine.` / `conflict.` / `spec.` 六族**，判定在起进程之前，全程走参数列表不拼 shell。
20. **门禁报告不存在时报「未跑」，不是绿也不是红。** 把没有的东西说成绿是面板最典型的骗人法。
21. **面板与 CLI 同源。** 任务详情直接调 `TaskStatusReport.RenderOne`，不另写一份渲染。
22. **供给对账同时查「哈希一致」与「产物齐全」。** 只比哈希会漏掉「有人手工删了一份知识文件」——指纹照样对得上，门禁照样绿。
23. **不给没跑过的外部接入写桩。** Aily 程序化导入验不了就如实写「未验证」，不留一段谁都没跑过、却长得像「已接入」的代码骗下一个接手的人。
24. **通用文档校验器复用 `需求.` 那一族规则 id**，不给每个实体另造一族——那些文案是字段级的、与实体无关。
25. **美术命令族用 `art.*` 不用 `asset.*`。** `asset.validate` 已被 Unity 资产管线占用，命令重名会让整个命令宿主起不来。
26. **变体本体 gitignore，边车全部进 git**（变体可由边车重生成）。规则要「排除 `变体/**` + 放行 `变体/**/` 目录 + 放行 `**/*.provenance.json`」三条齐全，只写排除的话 git 不会走进那棵子树，边车跟着丢。
27. **「收紧」的定义写死在代码里**：数字变小算收紧、布尔 `false→true` 算收紧、
    **字符串等其余一律算放宽**。第三条是刻意误伤——判紧会开出「把 `格式` 从 PNG 改成 JPG
    也叫收紧」这种口子；要覆盖就去基线的 `可覆盖` 里显式登记。放宽的值不采纳但合并继续走完，
    一次报全部问题。
28. **`moduleName` 必须一路穿到校验侧。** 「按带业务层的数据建、拿不带业务层的数据校」
    会让刚建出来的资产请求被自己的自检删掉。
29. **资产规格门禁逻辑放管线侧、命令放命令层，`Tools/Gates/` 下零新增文件**——延续决策 15。
30. **`driver.json` 的 `字段类型映射` 对非需求编辑端 driver 是空对象**，键必须在
    （`BridgeDriverDescriptor.Load` 必填），值空。不为此放宽加载器的必填清单——
    那会让真正缺字段的坏自述混过去。
31. **能力对账的探测输出走文件，不走真调用**；版本**不比对**，只查依赖「在不在」。
    没有真跑过的样本，定不出「差多少算不兼容」。
32. **专项认领入站走独立信封与独立收件箱子目录（`Pools/Inbox/Epics/`），不复用需求信封。**
    认领字段是「下游成员编辑所有、工程只读同步进来」，需求信封的所有权正相反；
    混在一起，幂等键与字段所有权两套语义会打架。
33. **入站只许改专项文件的 `认领` 与 `来源` 两个键**，其余字段一字不动；信封里多带的键
    **忽略并报一条 finding**——不静默吞掉，也不拒收整封。
34. **显式认领可跨默认职责，隐式认领不许。** 隐式两条硬前提缺一不写：该职责当前无人
    + 该 open_id 的默认职责包含这个职责。
35. **认领没写成功不算失败。**「已认领过」「该职责已有人」都是正常结果。
36. **选片走独立的 `SelectionOutboundPlanner`，不并进 `PoolPushPlanner`。**
    前者的单位是资产且不回写下游字段，后者的单位是需求且要回写；合并会逼着需求级
    事件表多带一个其余五个事件都用不上的「资产 id」参数。
37. **放行策略用自己的两值偏序，不套决策 27。** `自动放行 → 人审` 是**收紧**，
    照决策 27 的「字符串一律算放宽」会判反。决策 27 那条是刻意误伤（一般字符串
    说不清松紧），而放行值只有两个、松紧有定义，那个口子不存在。
38. **高危范围永不自动放行这条写在 `ReleaseDecider` 的代码里，先于策略查询判。**
    数据里的「可覆盖」清单本身也是数据、改得动，守不住底线。
39. **放行策略查不到的键返回 `人审`。** 与决策 10（引擎配置缺失返回值守）同理。
40. **`可覆盖` / `建议数阈值` / `高危范围` 只从基线读**，下层写了报 finding 并忽略。
41. **`ReleaseDecider` 四条判据全判完才返回**，一次报全部原因。
42. **「零 finding」与「对账/检查没跑成」必须分成两个分支。** 合并成一个会把崩掉的
    对账判成「一致」——决策 20 那类假绿的变种。凡是「没查出问题」的判定，
    都要先确认「查过了」。P2 批次 6 验收时真抓到过一次。
43. **坏数据在资产页不产行、在设计池页产行。** 资产请求坏了说明它还没成形；
    设计池文件坏了说明有东西烂在库里，必须让人看见。
44. **加工计划的规格值优先取资产请求，其次才是规格目录。** 只读目录会让 brief
    收紧过的值永远到不了加工步骤，决策 27 那条链路在这里断掉。P3 验收时真抓到过。
45. **加工计划必须幂等**：同输入逐字节相同，不许写时间戳/随机数/Guid/机器名/绝对路径；
    八个步骤对象恒在计划里，禁用只标记不删除。
46. **机检跳过的项必须报出来**，不静默跳过——把没查的说成查过是决策 42 的另一种长相。
47. **`包围盒上限米` 不进可覆盖清单**，它是拦「进 Unity 大一百倍」的保险。
48. **`tripo` 的 `试跑` 是空串**：没密钥没账号，试跑命令还不存在，空着比填个跑不了的诚实。
49. **`强制推送` 是挂账不是销账。** 状态留 `未决`、计入未销账，之后补选 `改新的`/`改旧的`
    才置 `已裁决`。把它也置成已裁决，会连同「已裁决不许覆盖」一起把销账路径堵死。
50. **同一条不许重复强制推送**：账已挂上，再挂只会把「挂了多久」查没。
51. **未销账不判红**——冲突不拦执行（总方案 §三），`gate.conflict` 只查格式。
52. **`ReplanPlanner` 不调执行后端、不写盘、不改工作项状态**，只产一份计划。
53. **依赖图必须防环**，`HasCycle()` 单独暴露给面板显示。
54. **不写常驻 daemon**，只落一次 tick 的判定与单实例锁。常驻进程在门禁里没法验；
    唤醒模式的事件订阅要经飞书 port，不在可验范围。循环是外壳，判定才是引擎。
55. **陈旧锁必须能被接管**（含锁文件读不动的情形）。断电留下一把解不开的锁会让轮询
    再也起不来，比偶尔多跑一个实例糟得多。
56. **值守压倒一切**：值守 + 队列有活 + 唤醒信号，照样不取活。唤醒只跳过间隔检查，
    不跳过模式判定——处理逻辑与轮询同一条，防漏。
57. **对外接口的中文键要配 ASCII 别名。** 认不出参数和「查无此物」返回同一个空结果，
    是决策 42 的又一种长相。

58. **抽查选取必须确定性，一个随机数都不许用。** 候选按 id 序数序均匀跨步取。
    随机抽查在门禁里没法验（同一份流水两次跑抽出不同结果），
    真发现问题时也没法复现「当初抽的是哪几条」。
59. **策略回落只写项目层，永远不写基线。** 回落方向永远是收紧（决策 37），
    在任意层都合法，所以不查 `可覆盖` 清单；但写进基线会把「基线是底线」这条弄脏。
    `PolicyFallbackPlanner` 里没有任何一处写得出 `自动放行`。
60. **抽查是销账动作，销了不许再挂回去。** 同一条流水不许重复抽查
    （会覆盖掉第一次的结论 = 销毁证据），也不许把 `抽查状态` 改回 `未抽查`。
    与决策 49 的挂账/销账语义同一套。
61. **`task.spotcheck` 一行 git 都不跑**，revert 只出计划文案。
    与 `ReviewPackageBuilder` 刻意不起子进程同一条道理——引擎不改历史。


62. **提案入库的幂等只挡「未关闭」（`待批` / `已批准`），不挡终态。** 同一类问题再犯
    就该再提一次；把 `已拒绝` / `已落地` 也当挡板，会让沉淀闭环卡死在第一次裁决上——
    拒过一次的问题以后永远提不起来。
63. **落地先产物、后状态，且 `PromotionLandingPlanner.Land` 一个字都不改提案状态。**
    产物写成了而状态没跟上，是「跑一次就好」；状态先跳到 `已落地` 而产物没写，
    是账上说做完了、盘上什么都没有——而 `已落地` 是终态改不回去，这笔账永远查不清。
64. **落地产物只追加、不覆盖既有规则。** 预审规则是合并写：项目层既有的规则一字不动，
    新规则追加在后面。覆盖写会把人手工改过的判定提示词无声抹掉。

65. **同步水位读不到时返回「空水位 = 全量拉」，`Advance` 只许前进，重拉走 `Rewind`。**
    读不到进度时最安全的是重拉一遍（幂等挡得住重复），不是不拉——这与决策 10
    方向相反是故意的。后退本身安全，但几乎总是参数搞错，还会把「同步到哪」抹掉，
    所以 `Advance` 拦「不小心后退」，`Rewind` 服务「故意重拉」。
66. **`ConflictDetector` 只算候选，不写盘、不调 `ConflictList.Append`。**
    探测与挂账是两件事（延续决策 52）。自动挂账等于让一个算错的相似度
    往协作层账本里塞垃圾；只有置信度「高」才建议发卡，中低只标注。
67. **同一对需求命中多条判据时，每条判据各产一条候选，不合并、不取最大。**
    合并会把「为什么判它冲突」压成一个数字，人就没法判断这次探测靠不靠谱。

68. **重规划落地的三道拒绝闸命中时磁盘零变化**：零脏项、有工作项还在「执行中」、
    脏集里有人改权威文件而人没确认。半落地的重规划比没落地糟——下次跑会以为
    已经重规划过了。带确认标志放行时仍要留一条「人已确认」的发现。
69. **净项的「保留」是一个字都不改，不是标一个「净」状态。**
    给没有变化的东西留下一次写入，会被人改检测（子文档 03 §三）误判成人改，
    此后引擎再也不重写那个文件。名单抄出来给人看就够了。
70. **需求快照既有版本永不覆盖，落地先证据后状态。**
    快照要逐字节写原文（不重新序列化、不美化、不排键）——它的价值就在于
    是当时那份原文。状态先跳到「停在关卡·方案」而快照没写，
    等于回了方案关却没有新基准可审。与决策 63 同源。

71. **「未决」的判据全仓只许有一套**，就是 `ConflictList.PendingCount()` 那套
    （状态不是「已裁决」，或选择是「强制推送」）。另写一套会让门禁说 3 条、
    审查包说 2 条——同一个账本两个数字，比没有数字更糟。
    冲突债务不改放行结论、不拦执行（决策 51），三个出口只摆账不加闸。
72. **assistant-package的文件清单有三份，加文件时必须一起改**：
    `AssistantPackageBuilder.PackageFiles`（真写哪些）、`ProspectiveFiles`（报产物）、
    **`AssistantPackageInspector` 自己那份（`gate.provision` 查「产物齐全」用的）**。
    P6 批次三只同步前两份，`gate.provision` 就明明缺文件却是绿的——
    决策 22 的「产物齐全」那一半当场失效。
    `PackageInspectorKnowsEveryFileBuildWrites` 那条测试就是拦这个的。

73. **PNG 解码器宁可如实拒绝，也不硬解。** 隔行、非零压缩法/滤波法、
    非调色板类型的低位深、非调色板类型带 `tRNS`、类型 1/5 保留值——一律拒绝并写清原因。
    硬解出一张错的图会一路算出看着很正常的色板距离，没人看得出它是假的（决策 23 同源）。
    **不校验 CRC，这一条必须写在类注释里**——不说明的话下一个人会以为校验过了。
74. **主色聚类全程确定性，一个随机数都不许有**（决策 58 同源）：
    固定步长抽样、按 (频次降序, 十六进制序数序) 播种、质心间隔 ΔE ≥ 12、
    距离相等归下标小的簇、空簇丢弃不重播种。
    **质心在 Lab 空间取均值**，不是 RGB 均值——RGB 均值在感知上往灰里偏。
75. **没有定稿色板就不许给距离。** 色板读不成/为空、图解不开、全透明，
    一律进「跳过」并写清原因，绝不产出「距离 0」的排名——
    那等于告诉人「这批资产全都符合风格」，而真相是根本没比过（决策 42）。
    跳过的项必须逐条列出来（决策 46）。

76. **面板脚本必须有语法健全性测试。** 那段 JS 住在 C# 的 verbatim 字符串里，
    一处写错的引号转义就让整份脚本语法错、十五页一页都不渲染，
    而**编译、单元测试、全量门禁全是绿的**——没有任何一道会去解析它。
    P4 批次二起面板就是全白的，直到 P7 批次二有人真去开了一次才发现。
    `CreationPanelScriptTests` 逐行查引号成对、查页面表点名的渲染函数真存在。
    **这只是启发式**，真正的保险是加完页面自己打开看一眼。
77. **「空账本」与「读不成」必须分成两支。** 文件不存在 → `Loaded=true`、总数 0
    （空是正常状态）；解析失败 → `Loaded=false`，**整页只给原因，一个统计数字都不给**。
    残缺的流水拿来印「问题 0 条」，比不显示糟得多（决策 42 的面板版）。

78. **密钥只判「键在不在」，值一次都不许取。** 面板判某个密钥配没配，
    只调 `TryGetProperty(..., out _)`，不放进任何返回字段、不写日志、不回显、
    不输出长度。密钥字段**不给输入框、不给保存按钮**——保存等于把密钥落盘，
    那不是面板该做的事（决策 5）。
    **`Tools/CreationPipeline/Config/local.json` 必须真的在 `.gitignore` 里**：这句话从 P1 就写在
    决策 5 上，却直到 P7 批次三才有人去补那一行。写在决策里不等于落了地。
79. **定稿是一稿一目录**：`Designs/Final/<名>/final.json`（子文档 06 §五，
    `FinalPalette.Load` 也照这个找）。只扫平铺的 `*.json` 会永远扫不到任何一份真定稿，
    功能全绿、测试全绿、门禁全绿，而那条路上根本不会有数据经过。
    名称取**目录名**，不取恒为「定稿」的文件名。
    **这类 bug 只有真开一次面板、真铺一份数据才看得见**（与决策 76 同源）。
