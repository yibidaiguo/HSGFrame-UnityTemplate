# 创作管线 · 锁定的设计决策（P8 起）

> 从 [创作管线锁定决策](创作管线锁定决策.md) 续号。那份写到 179 行，离 200 行硬顶不够放新条目。
> **改这里的任何一条都要重新走设计审查。** 决策 1–79 在上一份。

80. **执行后端 driver 按协议命名，不按厂商命名：`oaicompat`。**
    子文档 05 §八原本写的是 `claude`。不能用，理由是**门禁**：
    下游边界门禁把全部 driver 名当禁止串，逐行扫 `Tools/{CreationPipeline,Cli,Dashboard}`
    下的 `*.cs`，而 `claude` 这个词已经出现在那片代码的注释与文案里——
    选它等于当场点着门禁，而决策 17 说这道门禁不许加豁免。
    按协议命名还有个附带好处：DeepSeek / 通义 / 智谱 / 自建 vLLM 谁的 key 都能接，
    换厂商不改 driver 名、不动门禁。
    **推论：以后新增 driver 先拿名字去 `Tools/` 那三棵树里 grep 一遍，撞了就换名字，
    不要去加豁免。**

81. **daemon 是循环外壳，必须支持「跑满 N 轮自己退出」；无限循环是 `最大轮数=0` 的特例。**
    决策 54 当初写「不写常驻 daemon」，理由是「常驻进程在门禁里没法验」。
    有限轮把这条前提解掉了：门禁跑 3 轮、假时钟、假 sleep，判定链路全程可复现。
    决策 54 的另一半仍然成立且不许动——**外壳不做判定**：
    daemon 只干「取活判定 + 记账 + 消费唤醒」三件事，
    取到活之后真去执行工作项是别的命令的事（决策 52 同源）。

82. **唤醒事件源先落「文件投递」这一种，飞书事件订阅是另一条路。**
    `_Tasks/唤醒/*.json` 出现即算一次唤醒信号，处理后**移动**到 `_Tasks/唤醒/已处理/`，
    不删（决策 7：留证据，靠幂等挡重复）。
    这不是桩——它是一条真能跑通的唤醒通道，且不假装自己是飞书。
    飞书那条要么长连接、要么内网穿透，两条都要真租户，归 P8-7/P8-8。
    **信号必须在判定跑完之后才消费**：判定崩了信号要留着，
    否则信号丢了而账上什么都没有（决策 63 同源：先证据后状态）。

83. **一轮崩掉不许让 daemon 死掉，但也不许静默。**
    判定抛异常那一轮产一条 `判定跑成=false` 的记录、原因写异常消息，然后继续下一轮。
    `判定跑成=false` 与「这一轮没取到活」是两支，不许合并——
    合并会把崩掉的判定印成「队列里没活」（决策 42 的 daemon 版）。

84. **driver 实现落 `Bridges/<名>/src/`，不落 `Tools/`。**
    下游边界门禁的扫描根写死是 `Tools/{CreationPipeline,Cli,Dashboard}`；
    实现里必然要出现自己的 driver 名，落在 `Tools/` 下必红。
    `Bridges/` 是那道门禁的白名单（子文档 05 §六），且目录名全 ASCII，
    满足决策 1 的「含 .cs 的目录必须 ASCII」。
    **新工程必须加进 `Solutions/Template.sln`**，否则十秒级门禁编不到它，绿灯是假绿。

85. **driver 可执行的解析走 `Config/创作管线/下游.json` 的实现表，
    既不写进 `driver.json`，也不靠约定路径推导。**
    `driver.json` 是进 git 的共享契约，不该带本机路径；
    而按 `bin/<配置>/<框架>/` 推导会在 Debug/Release 切换、目标框架升版时静默失效——
    静默失效的表现是「找不到实现」被当成「下游没配」，那是决策 42 那类假象。
    实现表的值是**仓库相对路径**（bridge 是仓库内 build 出来的，跨机一致）；
    机器特有的东西（ComfyUI 地址、Blender 可执行文件、密钥）全在 `本机.json`。

86. **`本机.json` 不许预生成空值键。** 面板判密钥配没配只看键在不在（决策 78），
    预填 `"飞书应用密钥": ""` 会让面板显示「已配」，那是假绿。
    模板文件另起名 `Config/创作管线/本机.示例.json`，**填不了的键要求整条删掉**。
