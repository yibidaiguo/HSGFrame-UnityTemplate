# _Scratch · 模型试验区

AI（Claude / Codex / Kimi / DeepSeek 系工具等）本地测试产生的临时文件**全部放这里**，
本目录除本文件外整体被 git 忽略，永不上传。这是全仓唯一试验区，别在别处再开临时目录。

## 四条规则

1. **一次试验一夹**：`_Scratch/<主题>/`，夹里放一份几行的 `目的.md`——谁、在验证什么、
   何时可删。整个 `_Scratch/` 随时可清空，写清「何时可删」就是给清理者授权。
2. **内部分级照《规范/》执行，不另立规矩**：代码按「模块 → 职责」，
   资源按「类型 → 功能 → 模块 → 内容」，命名沿用前缀表与 PascalCase。
   试验区只豁免「是否上传」，不豁免「怎么摆、怎么命名」。
3. **只进不出**：正式区（代码、资产、文档、配置、脚本）一律不得引用 `_Scratch/` 里的东西。
   试验有结论要转正：资产走 `_Inbox` 归档，代码按模块落位，结论写进日志——转正是单独提交。
4. **纯一次性的碎片优先放会话自己的系统临时目录**，跨步骤、跨会话要复用的中间产物才进 `_Scratch/`。

## 与门禁的关系

- git 忽略 ⇒ 改动白名单门禁看不见它，不会红
- `.meta` 完整性只扫 `UnityProject/Assets/` ⇒ 无关
- 目录名以下划线开头是**有意**的：它在 `gate-config.json` 的 `underscoreExemptNames`
  三个长期白名单之列，语义是「此处内容由机器管理，不是人手维护的正式品」

也就是说：门禁对试验区几乎零约束，约束靠上面四条自觉——这正是它被隔离在正式区之外的原因。
