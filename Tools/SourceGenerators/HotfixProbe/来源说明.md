# 热更程序集用的两个源生成器从哪来

Unity 侧 `Assets/_Project/Scripts/Hotfix/` 下有两个 dll，都带 `RoslynAnalyzer` 标签，
**不是普通托管插件**：它们是编译期的源生成器，产物随 `Hotfix.Logic` 一起编出去。
放在这个目录是有讲究的 —— Unity 按目录把分析器挂到程序集上，
分析器要与 `Hotfix.Logic.asmdef` 同目录才会作用到这个程序集。

| dll | 来源 | 干什么 |
|---|---|---|
| `Template.Hotfix.Analyzer.dll` | 本目录的 `HotfixProbeGenerator.csproj` 现编 | 往所在程序集里写一个探针类型 `Template.Hotfix.Generated.HotfixSourceGeneratorProbe`，回答「源生成器产物能不能落进热更程序集」（方案验证 3） |
| `System.Text.Json.SourceGeneration.dll` | NuGet 包 `System.Text.Json` 8.0.5 的 `analyzers/dotnet/roslyn4.0/cs/` | 补全 `HotfixJsonContext` 这个 `JsonSerializerContext` 的实现体（方案验证 7） |

## 重新编出 `Template.Hotfix.Analyzer.dll`

```bash
dotnet build Tools/SourceGenerators/HotfixProbe/HotfixProbeGenerator.csproj -c Release
```

产物在 `bin/Release/netstandard2.0/Template.Hotfix.Analyzer.dll`，拷到
`UnityProject/Assets/_Project/Scripts/Hotfix/` 覆盖同名文件即可，`.meta` 不要动
（`.meta` 里的 `labels: - RoslynAnalyzer` 与「所有平台都不勾」是分析器不被当成插件的关键）。

**Roslyn 版本必须不高于编辑器自带的那个**（6000.3.11f1 是 4.3.1，
查法：`(Get-Item '<编辑器目录>/Data/DotNetSdkRoslyn/Microsoft.CodeAnalysis.CSharp.dll').VersionInfo.ProductVersion`）。
高了编译器加载不了这个生成器，而且**不报错**，症状是产物里什么都没有。

## 取另一个 dll

`System.Text.Json` 的源生成器随包发布，取法与 `Assets/Plugins/SystemTextJson/` 那四个 dll 同源：

```bash
# 包已在本机 NuGet 缓存里时直接拷
cp ~/.nuget/packages/system.text.json/8.0.5/analyzers/dotnet/roslyn4.0/cs/System.Text.Json.SourceGeneration.dll .
```

`roslyn4.0` 那个目录对应 Roslyn 4.0~4.3；编辑器升级到 Roslyn 4.4 以上时改取 `roslyn4.4`。
