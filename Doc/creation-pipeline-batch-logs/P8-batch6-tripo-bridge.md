## 二、我判错过一次，这里留着当教训

上一轮 Claude 看到 `GET /user/balance` 回 `{"balance":0,"frozen":0}`、
而账号控制台上显示 200 免费积分，**推断成「免费积分不进那个字段，所以余额接口不可信」**，
还据此写进了决策 91。

真提交一次任务之后，拿到的是：

```
403  {"code":2010,"message":"You don't have enough credit to create this task",
      "suggestion":"Please purchase more credit"}
```

**`balance: 0` 一直是准的。** 控制台那 200 积分**不能用于 API 调用**。

两次都指向同一个结论（余额接口不能当就绪判据），但**理由完全相反**：
第一次以为它漏报，实际是它没漏报、是控制台那个数与 API 无关。
决策 91 的正文已改，并把这次判错留在里面：

> **两个数字对不上时，不许挑一个顺眼的去解释另一个——去真跑一次，让第三个事实来裁决。**

## 三、验收时改的一处：报错在说谎

桥原本把 HTTP 403 一律映射成 **`凭据无效` / 「密钥无效或无权访问」**。
而真实原因是积分不足——**密钥完全是好的**。
这条报错会让人跑去换 key、查权限，查一整天查不出问题。

tripo 的 403 有两种，按响应体的 `code` 分：

| code | 含义 | 映射 |
|---|---|---|
| 2010 | 积分不足 | `额度不足`，人话写「**不是代码坏了**，请到下游控制台确认剩余积分」 |
| 1005 | 该密钥无权访问此资源 | `凭据无效` |
| 无 body | 退化 | `凭据无效` |

**Claude 独立复跑过一次**（403 不消耗积分），确认现在报的是
「额度不足……不是代码坏了」，且输出目录根本没被创建——失败不留半个文件。

## 四、顺带失效的一条：决策 48

决策 48 说「tripo 的 `试跑` 是空串：**没密钥没账号**，试跑命令还不存在，
空着比填个跑不了的诚实」。

**现在有密钥了，那个前提没了。** `driver.json` 的 `试跑` 已改成
`bridge.model --Driver tripo --DryRun true`——干跑不花钱、没网也能跑，
用它当试跑命令比空着有用。
