# 需求文档同步 B 批 · 文档规范、doc.render 与 gate.reqdoc

> 上游：[需求文档与任务同步 · 形状细节](../requirement-doc-and-task-sync-shapes.md) 第五节。
> 前一批：[A 批 · 需求目录化](REQDOC-batchA-requirement-directory.md)。

## 一、落了三样

| 东西 | 落点 |
|---|---|
| 文档规范基线 | `Specifications/Baseline/requirement-doc.baseline.md` |
| 生成/刷新命令 | `doc.render`（`Tools/CreationPipeline/RequirementDocumentRenderer.cs`） |
| 门禁 | `gate.reqdoc`（`RequirementDocumentChecker.cs`），已挂进 `gate.ps1` |

## 二、规范与它的机器可读形式住在同一个文件里

基线是一份 md：给人读的散文 + 一段 ```json 契约，`doc.render` 与 `gate.reqdoc`
都只读那段 JSON（锚在「机器读的那份」那个小标题上）。

**为什么不拆成「散文一份、配置一份」**：散文与配置分家的规范活不过三次改动——
改的人只会改自己看得见的那一份，然后两份说的话开始不一样，
而门禁执行的是没人读的那一份。

项目层用 `Specifications/Project/requirement-doc.json` 追加小节与 frontmatter 键。
那个文件**只表达得出「加」**（两个键都叫「追加…」），
所以「基线定的不可删」这条规矩靠形状保证，不靠校验器事后骂人。

## 三、frontmatter 只认三种形状，是故意的

标量、一层嵌套映射、对象列表——就这三种，写在基线第三节里。
认不出来的写法**不报语法错，而是读不出那个键**，于是「必备键缺失」替它报红。

两个理由：不必往工具链里拖一个 YAML 依赖；写文档的人不会掉进 YAML 那些
反直觉的角落（`是`、`否`、`12:30` 各有各的惊喜）。
报「缺必备键『权威侧』」比报「第 7 行缩进不对」有用得多。

## 四、doc.render 刷新时只加不改

人写下的每一个字原样留着，工程只补三样：

1. 工程所有权的 frontmatter 字段（`需求id` / `标题` / `类型` / `状态` / `生成区hash`）
2. 缺掉的必填小节——插在「按规范排在它后面、且已经在位」的那一节之前，不是甩到末尾
3. 生成区整段重生成

`文档版本` 与 `权威侧` 只在缺的时候给初值（1 / 项目），之后归人。

**一个会重写人写的段落的渲染器，第二次就没人敢跑了；没人敢跑的生成器等于没有。**

小节正文的来源是需求骨架里的同名字段：`目标` / `玩法` 这些分类型必填字段照抄，
`验收标准` 是数组，渲成有序列表。没有同名字段的（`边界与不做`）摆一行「（待补）」。

**幂等**：连跑两次结果逐字节相同，单测钉着。第一版不是——
frontmatter 后面那个空行每跑一次多长一个，两次结果不一样的生成器等于没有幂等门禁。

## 五、门禁查六条

1. frontmatter 必备键齐全（外加「权威侧」取值合法）
2. `需求id` 与目录名一致
3. 必填小节按规范定的顺序在位
4. 验收标准非空且是有序列表——散文写的验收标准就是要拦的那种，**阶段 4 逐条核，核不动散文**
5. 媒体：登记的文件真存在、文件名 ASCII、每条带说明；正文里引用的 `media/…` 也要存在
6. 生成区没被手改（`生成区hash` 与正文实际哈希比对）

**没有 `index.md` 不算违规**：需求可以先有骨架后有文档，`doc.render` 随时补得出来。
门禁查的是「写了的那份对不对」，不是「写没写」。

哈希这条要连着查「有生成区却没记哈希」，否则把那一行删掉就等于绕过第 6 条。

## 六、顺手修的一个假红：命名门禁不认原始字符串

`NamingChecker.StripNonCode` 认逐字串（`@"…"`）与插值串（`$"…"`），
**不认 C# 11 的原始字符串**（`"""…"""`）。它把 `"""` 看成「一个空串加一个开引号」，
于是原始串里**没被引号裹住**的中文（markdown 正文、样例文档）被当成标识符报出来——
这一批的三个测试文件换来 97 条假红。

装样例的原始串正是测试最该用的东西，所以这一路必须认：加了一个带
`ref int rawStringFenceLength` 的重载（栅栏长度要记，`""""` 不能被三个引号收尾），
三个调用点一起换过去，旧的三参重载留着不动。新增 4 条单测钉住。

## 八、已知缺口

- **仓库里还是一条需求都没有**，所以 `gate.reqdoc` 在真门禁里是空跑绿。
  第一条真需求进来之前，这一道证明不了什么。
- `media/` 的 ASCII 归一还没做：门禁会报中文媒体名，但**没有人负责把它归一**。
  设计里写死了不许复用资产名归一化器（那个现在产中文名），归一器本身留给 C 批。
- `参考媒体` 是选填小节，`doc.render` 不会主动建它；
  frontmatter 的 `媒体` 登记也还没人写——那是 C 批 `doc.normalize` 的活。
