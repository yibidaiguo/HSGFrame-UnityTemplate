> 环境我自己装，**只有密钥和账号标识必须你来填**——我全程不碰密钥的值。

## 一、怎么填

1. 把 `Config/创作管线/本机.示例.json` 另存为同目录的 **`本机.json`**。
2. 按下表填值。**填不了的键整条删掉，不要留空串。**
   面板只判「键在不在」、不读值（决策 78），留空串会显示「已配」，那是假绿。
3. `本机.json` 已经在 `.gitignore` 里，永不入库（决策 5）。

## 二、要填什么

| 键 | 去哪拿 | 缺了会怎样 |
|---|---|---|
| `飞书应用密钥` | 飞书开放平台 → 你那个自建应用 → 凭证与基础信息 → **App Secret** | bridge-feishu 试跑跑不了 |
| `下游配置.feishu.应用标识` | 同上一页的 **App ID**（`cli_` 开头，不是密钥，但一起填省事） | 同上 |
| `下游配置.feishu.多维表格标识` | 那张多维表格的 URL 里 `base/` 后面那一段 **app_token**（`bascn` 开头） | 铺表跑不了 |
| `模型生成密钥` | tripo 控制台 → API Key | bridge-tripo 试跑跑不了 |
| `执行后端密钥` | 你说要另配的那个 LLM key | AI 对抗预审、语义冲突比对跑不了 |
| `下游配置.oaicompat.地址` + `.模型` | 那个 key 对应的 **OpenAI 兼容 base URL** 与模型 id | 同上 |

## 三、飞书那边还要做三件事（在开放平台点，不在这里填）

1. **开权限**：`bitable:app`（多维表格读写）、`im:message`（发消息卡片）、
   `contact:user.id.readonly`（成员表要 open_id）。开完要**发布版本并等审核通过**，
   否则 token 拿得到但调用一律 403。
2. **把机器人拉进那张多维表格**：多维表格 → 右上角「…」→ 添加文档应用 → 选你的自建应用。
   不加这一步，app_token 对得上也读不到表。
3. **事件订阅**（只有唤醒事件源那一项要）：先留空。
   本机没有公网回调地址，这一项走**长连接**还是**内网穿透**要另说，
   我会在做到那一批时把两条路的差别写清楚再问你。

## 四、执行后端那个 key：任何 OpenAI 兼容服务都行

驱动按**协议**写，不按厂商写（决策 80），所以 DeepSeek / 通义 / 智谱 / 自建 vLLM
随便哪个都能接，只要它认 `POST {地址}/chat/completions`。
示例文件里预填的是 DeepSeek 的地址和模型名，不是你的，按你自己的 key 改。
