## 二、「尺寸」就是那条证据

图生图跑通不跑通，最难的是**怎么证明它真的读了那张参考图**——
出来的图长什么样是主观的，字节数不能自证。

**证据是尺寸**：参考图 `Suzanne_BaseColor.png` 是 **1024×1024**，
而文生图那条路的尺寸来自 `EmptyLatentImage`（配方里写 256，请求里写 512）。
产出是 **1024×1024** —— 只有 `LoadImage → VAEEncode → KSampler.latent_image`
这条链真的执行过，尺寸才会跟着参考图走。

**找一个「只有真跑对了才会出现」的确定性数字**，比盯着图看可靠得多。

第二条证据是**换图**：种子不变、只换参考图（同尺寸的另一张贴图），
产出从 1189010 字节变成 1087565 字节。
**敢说「是」也要敢说「不是」**——同图同种子必须一模一样，换图必须不一样，
两条都真跑过才算这条链路是活的。

## 三、拆穿一个骗人的锚点槽

`icon@v5`（原 `图标@v5`）的 `mapping.json` 里挂着：

```json
"锚点槽": [ { "槽名": "参考图", "节点id": "5", "参数名": "image" } ]
```

而节点 5（`LoadImage`）**不在主链上**——ComfyUI 不执行没被引用的节点。
也就是说：**配方声称有一个能注参考图的槽，注进去也没有任何效果，而且不报错。**

这与另一个会话这一轮点出的两条是同一族：
「一个叫『试跑』的按钮跑的是真的」、「面板读一个从来没人写的报告文件」。
共同形状是 —— **接口在、语义不在，而且不报错**。

**改法是删掉那个槽，不是留着标注「暂不生效」**：
注释只有读代码的人看得到，删掉才是配方本身不再撒谎。
图生图另起一份配方 `icon-img2img@v1`（`LoadImage → VAEEncode → KSampler`，`denoise 0.6`）。

## 四、反向验证（三条，都真跑过）

| 造的坏输入 | 结果 |
|---|---|
| 文生图配方 + 给参考图 | `配方「icon@v5」没有名叫「参考图」的锚点槽，填不进去` |
| 图生图配方 + 不给参考图 | `配方「icon-img2img@v1」有「参考图」锚点槽，必须给参考图路径` |
| 槽指向不存在的节点 | 翻译期报错（单测覆盖），不产一张断图 |

第二条**原来的表现是下游的话**：`LoadImage | Permission denied: 'D:\Tools\ComfyUI\input'`——
看的人根本对不上「我忘了给参考图」。所以那一条改成在桥里当场拦下。

## 五、边车不记参考图 = 重生成不出来

第一次真跑之后边车里是 `风格锚点: {}`。**图生图那张参考图是决定成品长相的最大变量**，
边车不记它，拿着边车重生成不出来——而边车看上去是齐全的，那是最糟的一种缺。
现在把「这一次真正填进去的锚点取值」并进边车的风格锚点。

## 六、变体落正式落点

`bridge.generate` 的 `--OutputDirectory` **改成可选**：留空就按资产请求里的
「需求id」与「id」算 `_Tasks/<需求id>/30-outputs/<资产id>/`。
真跑业务流程时变体本来就该落那儿，不该每次由调用方现编一个目录。

验收残留已清（`_Tasks/REQ-9001/` 与 `_Scratch/img2img验证/` 都删了，决策 4）。

## 七、已知缺口

- **只有两个配方**（`icon@v5` 文生图、`icon-img2img@v1` 图生图），其余资产类型仍然没有。
- **`denoise` 写死 0.6**，没有从请求里取——「参考图影响多大」目前是配方级常量，不是请求级参数。
- ComfyUI 侧仍是**单机单实例**：`/upload/image` 把图传进那台机器的 `input/`，
  换一台下游就要重传——这在 driver 契约里没有任何地方写着。
