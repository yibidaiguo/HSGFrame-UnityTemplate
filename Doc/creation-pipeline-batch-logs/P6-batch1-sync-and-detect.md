# 创作管线 · P6 批次 1「同步与探测」日志

> 总账在 [创作管线进度](../creation-pipeline-progress.md)。本文只装这一批的落地记录与验收证据。

## 这一批真正做的是什么

三件都是前几批留下的确定性缺口，共同点是**账挂上了却没人算**：

1. **同步水位**：`pool.pull` 一直全量扫，子文档 02 §二第 1 步那句
   「轮询按最后修改时间 > 水位拉增量」没有落点。
2. **冲突自动探测**：`ConflictList.Append` 早就有，但**没有任何东西会去调它**——
   冲突至今只能手工挂。
3. **裁决流水**：`conflict.resolve` 就地改两个键，所以**补选会覆盖掉上一次的裁决**。
   「当初是谁强制推送的」在补选之后再也查不出来（P4 批次 1 记的那条缺口）。

## 水位为什么「只许前进」，重拉却另开一扇门

读不到水位文件时返回**空水位 = 全量拉**——这与决策 10（配置读不到返回值守）方向相反，
是故意的：同步的最安全行为是重拉一遍（幂等会挡掉重复），不是不拉。

但 `Advance` **拒绝后退**。后退本身是安全的（重拉靠幂等吃得下），
可它几乎总是搞错了参数，而且会把「已经同步到哪」这条线索抹掉。
所以后退走 `Rewind` 这扇正门——**`Advance` 拦的是「不小心后退」，
`Rewind` 服务的是「故意重拉」**。同一时间重放算幂等，成功但不算前进。

## 探测器为什么只算不挂账

`ConflictDetector` 一个字都不写盘，也不调 `ConflictList.Append`——
**探测出候选和挂账是两件事**，延续决策 52（`ReplanPlanner` 只出计划）。
自动挂账意味着一个算错的相似度就能往冲突列表里塞垃圾，而冲突列表是协作层的账本。

三条判据（模块有交集才比标题的 bigram Dice、共用设计记录、同专项下验收标准逐字重合）
**命中几条就产几条候选，不合并、不取最大**。合并会把「为什么判它冲突」压成一个数字，
人就没法判断这次探测靠不靠谱。只有置信度「高」才建议发卡，中低只标注——
子文档 02 §二第 4 步那句「低置信度只在需求上标注，不发卡」。

## 先流水、后状态

`ConflictList.Resolve` 在改「状态」之前先写流水，**流水写失败就整个裁决不执行、
状态一个字不改**。理由与决策 63 同源：流水写了状态没改是「跑一次就好」；
状态改了流水没写，是证据永远丢了——而这正是本批要修的那个缺口本身。

`Pools/Designs/冲突裁决流水.json`（协作层，只追加）。

`conflict.resolve` 输出追加一行「本条冲突累计 N 次裁决」。

**门禁**：不新增，扩 `gate.conflict` 加四条流水检查（加载失败、序号连续性、
选择合法性、指向的冲突存在）。结论行变成
「冲突可见门禁（冲突 N 条，未销账 K 条，裁决流水 M 条）」，
**未销账与流水条数都不判红**（决策 51）。

## 执行后端这一轮报上来的

1. **`需求id` 中文参数键别名没做成**。查过了，**它是对的**：命令框架
   （`CommandRegistry` / `CommandArgumentBinder` / `CommandArgumentValidator`）
   一律按 CLR 属性名匹配参数 JSON 的键，`[JsonPropertyName]` 会被默认值填充覆盖。
   决策 57 说的是「中文键要配 ASCII 别名」，而这里**规范名本来就是 ASCII**，
   传中文键会得到明确报错而不是静默空结果——决策 57 的意图已经满足。
   任务书那条是我写错了，不是它没做到。
2. `WatermarkAdvanceResult` 的工厂名 `Succeeded` 改成 `Success`（与同名属性编译冲突）。
   照 `ConflictResolutionResult` 的范本，合理。
3. 三份新测试要登记进 `test-baseline.json`——它改不了那个目录，由 Claude 补，已补。
