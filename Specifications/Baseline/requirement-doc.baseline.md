# 需求文档规范 · 基线

一条需求在仓库里是一个目录（`Pools/Requirements/REQ-0042/`，决策 99），
目录里的 `index.md` 就是这份规范管的东西：需求的正经文档，人看得懂，AI 定位得到。

规范分两层：**这份基线由模板发**，项目层可以在
`Specifications/Project/requirement-doc.json` 里**追加**小节与 frontmatter 键，
**删不掉基线定的任何一条**——那个文件的形状只表达得出「加」，表达不出「删」。


## 二、为什么这么定——三条都是给 AI 定的

1. **章节标题是契约，不是排版。** 名字与顺序由这份基线固定，AI 定位靠标题，不靠猜段落语义。
   缺了必填小节 = 门禁红，不是「凑合能读」。
2. **机器要读的东西一律结构化。** 需要判定的字段进 frontmatter；
   验收标准必须是**有序列表、一条一句、单条可判真假**——阶段 4 是逐条核的，
   一条里塞三件事就核不动。散文写的验收标准由 `doc.normalize` 提成列表，提不动就打回。
3. **AI 看不见图，但看得见说明。** 所以媒体在 frontmatter 里**必须带说明**，
   而且说明要写「图里有什么」而不是「这是一张图」。这条是「优先 AI 友好」在媒体上的全部含义。

## 三、frontmatter 认哪三种写法

解析器只认下面三种形状，别的写法一律当没写（不是报错，是读不出来，
于是「必备键缺失」会替它报红）：

| 形状 | 例子 |
|---|---|
| 标量 | `标题: 七日签到` |
| 一层嵌套的映射 | `同步:` 换行后缩进两格的 `节点token: wikcnXXX` |
| 对象列表 | `媒体:` 换行后 `  - 路径: media/a.png` 再缩进的 `    说明: …` |

值里的 `#` 之后算注释；要写井号本身就把整个值用引号裹起来。

## 四、媒体

| | 仓库侧 | 飞书侧 |
|---|---|---|
| 图片 | `media/*.png`，md 里相对路径引用 | 转成 docx 图片块 |
| 视频 | `media/*.mp4` | 附件块 + 链接 |
| 大文件 | 超过阈值不进仓库，只在 frontmatter 记外链 | 同左 |

`gate.pathascii` 仍然管着：`media/` 底下的文件名全 ASCII。
**媒体入库要走 ASCII 归一，不许复用资产名归一化器**——那个现在产中文名。

## 五、门禁 `gate.reqdoc` 查六条

1. frontmatter 必备键齐全
2. `需求id` 与目录名一致
3. 必填小节按基线定的顺序在位
4. 验收标准非空且是有序列表（`1.` `2.` …，不是 `-`）
5. 媒体：frontmatter 登记的文件真存在、文件名是 ASCII、每条都带说明；正文里引用的 `media/…` 也真存在
6. 生成区没被手改（`生成区hash` 与生成区正文的实际哈希比对）

**没有 `index.md` 不算违规**——需求可以先有骨架后有文档，`doc.render` 随时补得出来。
有 `index.md` 就得合规。

## 六、机器读的那份

下面这段 JSON 是 `doc.render` 与 `gate.reqdoc` 真正读的契约。
改上面的散文不影响判定，改这段才影响——**两边要一起改**。

## 七、项目层怎么加

`Specifications/Project/requirement-doc.json`，只有两个键，都只表达「加」：

```json
{
  "追加小节": { "系统": ["埋点"] },
  "追加frontmatter必备键": ["负责人"]
}
```

追加的小节排在该类型必填小节的**后面**，顺序按这里写的来。
